# im2agent · v0.6.1 之后的缺口补全清单（商业化前必须做）

> 这份清单对应你提出的三项缺口（登录实名 / WebSocket 横向扩展 / 支付网关防白嫖），
> 加上我们自己审计出的两项（合规与审计留存、多租户隔离）。
> 每项写：**为什么现在不做不行** → **最小可行实现** → **验收标准** → **明确不做什么**。

## 一、第三方登录与实名认证（合规底线）

**为什么**：IM + 付费 + 陌生人触达，在国内属于"实名制 + 内容责任"双重监管对象；没有实名就没有可追责主体，付费争议也立不住。

**最小可行**
1. OAuth2 授权码流：微信开放平台 / Apple Sign in（海外）；回调后**只取 unionid/openid，不取关系链**。
2. 手机号验证码兜底（国内主路径），与 OAuth 账号在 `account_identities` 表做多对一映射到主账号。
3. 实名：身份证号 + 姓名走持牌三要素核验服务（**平台不存明文**：只存 hash + 核验结果 + 时间戳）。
4. 会话：短期 access token + refresh token；`ADMIN_TOKEN` 仅用于运维面，**不能当用户态**。

**验收**：未实名账号不能发起/接收陌生人付费消息；实名信息可删除、可导出；登录态跨设备撤销 ≤1 次请求生效。

**不做**：不接个人微信（无官方 Bot API，合规风险不可控）；不做"身份证照片 OCR"（超范围收集）。

## 二、WebSocket 网关横向扩展（10 万+ 设备）

**为什么**：单节点 Go 网关支撑几千并发；一旦做熟人群 + 在线状态，跨节点广播是硬需求。

**最小可行**
1. 网关层无状态化：连接落在哪个节点由 LB 粘性/连接 ID 决定；**在线状态与订阅关系放 Redis**（`ZSET` 心跳 + `HSET` 订阅）。
2. 跨节点广播：`Redis Pub/Sub`（或 NATS）按 `channelId` 扇出；节点只投递本地持有的连接。
3. 消息序号：按会话分片的分配器（主仓库 `§10 seq` 的 64 分片思路），别用全局锁。
4. 断线补拉：客户端带 `lastSeq`，网关从存储补发；`CMD` 类不补发。

**验收**：单节点断连，客户端 5s 内重连并补齐；跨节点 A 发 B 收 P99 < 200ms（内网）；扩容后在线状态不丢。

**不做**：不自己实现共识/分片迁移（至少在 DAU 50 万前不碰）；不把消息正文塞 Redis 当存储。

## 三、支付网关对接与"防白嫖"

**为什么**：现在 `ledger` 只是记账，钱没真正流动；而"看到且回复才扣费"天然会被退款机制攻击。

**最小可行**
1. 接支付宝/微信支付（**先做代收，不做分账**；分账涉及二清，需牌照或持牌机构合作）。
2. 扣费模型：预授权/冻结 → 查看并回复 → 捕获；或"先充值余额，按次扣减"。**不要用"先扣后退"**（退款被滥用）。
3. 防白嫖四条：
   - 每对（sender→receiver）**每日发送上限**（主仓库 `dailySendCap` 已实现）；
   - 退款窗口 **仅限未回复**（`REPLIED` 后走人工争议）；
   - 平台侧**风控画像**：短时间大量陌生人消息、同一设备多账号、Agent 生成内容的重复率；
   - **Agent 预审在前**：付费永远不能绕过预审（主仓库铁律）。
4. 对账：`ledger` 与支付渠道日切对账，差异 > 0 即告警；幂等键与渠道单号双向可查。

**验收**：连点 10 次支付只产生 1 条 CHARGE；退款只发生在未回复态；对账日切差异为 0。

**不做**：不做二级清算/资金池；不做"付费就能进白名单"（那会把过滤机制卖成漏洞）。

## 四、合规与审计留存（产品上线前置）

**为什么**：内容审核与审计链是"平台已尽义务"的证据；PaaS 后台日志不能当证据。

**最小可行**：自有审核链（规则版本 + 模型版本 + 命中 + 人审 + 申诉）→ 签名审计（主仓库 `§16`）→ 按监管要求留存周期与调取流程；用户删除权与审计留存冲突处，由法务出结论后写进隐私政策。

**验收**：任一付费消息可从 `messageId` 追到「谁审的、什么规则、何时、谁批的」。

## 五、多租户隔离（若做企业群/公司群）

**为什么**：公司群属于"组织数据"，与个人信任档混用会同时破坏两者。

**最小可行**：`tenant_id` 贯穿存储与审计；组织角色**不得映射为个人信任档**（主仓库 `docs/16` 铁律）；跨租户默认禁止，需显式授权。

**验收**：租户 A 的管理员无法读取租户 B 的任何会话/账本/审计。

## 六、优先级建议

| 顺序 | 项 | 理由 |
|---|---|---|
| P0 | 登录 + 实名 + 支付（代收 + 余额扣减） | 没有这三项不能对真实用户开付费 |
| P0 | 审核链 + 签名审计 | 合规前置，事后补代价最大 |
| P1 | WS 横向扩展 | 熟人圈内测（<1 万 DAU）可先用单节点，但要在 1 万前完成 |
| P2 | 多租户 | 只有在做企业群时才需要 |
