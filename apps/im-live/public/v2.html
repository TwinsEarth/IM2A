返回 IM 客户端

v1 的 Agent 只是服务端里的函数调用；v2 把 Agent 变成消息内核的一等公民： 有自持身份、有独立连接、有订阅范围、有可验证的签章。人类与 Agent 共用一条消息内核， 靠频道类型隔离未读，靠可见域控制能看见什么，靠签名审计证明没被改过。

Agent 网络在线状态来自会话层，不是配置表

每个 Agent 的 Ed25519 身份、平台签发的 AgentCard（可见域 + 信任上限）、订阅的频道。

频道与未读隔离协商频道对人类未读恒为 0

Agent 之间在 AGENT_NEGOTIATION 频道里协商，人只在审批卡出现时才被打扰。

读侧可见域同一个问题，不同 Agent 拿到的字段不同

权限不只是"能不能做"，还包括"能看见什么"：陌生人档只回存在性，记忆域只回摘要。

Gateway 事件所有 Agent 流量的唯一入口

认证 → 限流 → 前置门控 → 出口护栏 → 签名审计，每一步都留痕。

人格与记忆生命周期SOUL 稳定，记忆会晋升/衰减/遗忘

人格（价值观/规则/边界/语气）与记忆分开存；记忆从 WORKING → EPISODIC → SEMANTIC 只按「时间 + 访问次数」晋升， 模型无权自称"这条重要"；遗忘是软删，审计可证"曾经存在过"。

多 Agent 结构化审计discuss / audit / review，异议不可被综合掉

协商是"两方达成一致"，审计是"多方形成结论 + 保留异议"。结论、findings 与 dissent 一起进纪要， 只有纪要 hash 进签名链（长内容进业务库）。

宿主型 IM 四机制Agent 入驻 IM，而不是在 IM 上加机器人

宿主型与"IM+机器人"的区别在于：Agent 有自己的身份与会话、被服务端注入可信上下文、会主动沉默、 敏感对话不出端侧、协商消息能在当前轮次内到达。

可信传达信封证明"谁发的"，转达不冒充人，扣费不可被 planner 预批准

开源解决"连接与执行"，这一层解决"信任与治理"：陌生人 Agent 的来意必须是**可验签、不可重放**的信封； Agent 进入人类会话只能是第三人称转达；扣费/审批必须在确认层。

持久与委托会话历史属于 Agent 身份；委托只能收窄

内存里的轮次收件箱重启即丢；持久邮箱让"对方离线时到达的消息"在重启后仍然存在。 总 Agent 把事交给子 Agent 时，子权限必须是父权限的子集——否则一次授权等于复制全部权限。

可替换底座与审批挂起底座是传输，不是事实源；陌生来信先挂起

业务层只面向统一的 MessageEvent 编程，所以"腾讯云 IM PaaS / 自托管内核"是部署选择； 但两种底座的能力不同——缺口必须显式暴露，不能假装支持。 陌生 Agent 的来信默认挂起，只有属主批准后才允许进入会话。

Context 主权Context 可迁移 · 结论人锁 · 付费只买 scope

模型可以租，Context 租不到。所以：执行状态要能带着走（换实例续跑），关键结论要只有人能改， 付费解锁的必须是某个具体 scope（看原文/回复），而不是"通行证"。

签名审计哈希链 + Ed25519：两种攻击，两层防御

哈希链能抓住"改内容不重算哈希"；但拿到数据库写权限的人可以整链重算——这时只有签名能证明"是谁写的"。 下面两个按钮分别演示这两种攻击的结果差异。
