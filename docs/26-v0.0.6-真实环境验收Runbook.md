> 版本 v0.0.6（R17 对齐）· 对应契约 `contracts/INTERFACES.md` v1.0（变更记录 **R17**，§45–§46）· 作者：架构组
> 定位：用户指令「按清单开始 v0.0.6 的开发」。**v0.0.6 不新增业务能力**，而是把「本机全绿」变成「真实可验收」：先跑**预检**（可达/鉴权/持久/真实依赖/时钟），再对真实目标跑 Gate，输出可归档报告；**不能自动化的显式 `MANUAL`，不假装通过**。

## 1. 版本定义

### 1.1 「本机全绿」→「真实可验收」

| 维度 | v0.0.5（本机/内测） | v0.0.6（真实环境验收） |
|---|---|---|
| 证据 | 本机 `node <file>.test.mjs` 全绿 | 对**真实 target** 跑 A–E 33 条 Gate，输出报告 |
| 前置 | 无（直接跑测试） | **预检**：可达/鉴权/持久/真实依赖/时钟/TLS，不过不跑 |
| 不可自动化项 | 容易口头“应该没问题” | 显式 `MANUAL` + 责任人签字 + 证据留存 |
| 报告 | 终端输出 | 可归档 JSON/MD（含 target/时间/summary） |
| 结论 | “代码没问题” | “**这个部署**在真实环境满足验收口径” |

### 1.2 工具能力边界（先写清，避免“假装通过”）

## 3. 33 条 Gate 转执行表

> 口径：`AUTO` = 可由 §46 默认 Gate 直接执行；`CUSTOM` = 需注册自定义 Gate（**v0.0.6 CLI 未内置，当前按 MANUAL 处理**）；`MANUAL` = 必须人工签。
> 汇总：**AUTO 2 条**（D1、E4）；**CUSTOM 15 条**（当前按人工签）；**MANUAL 16 条**。**当前实际：2 自动 / 31 人工**（不许口头通过）；未来若实现自定义 Gate，最多 17 自动 / 16 人工。

| Gate | 判定要点（取自 docs/21–25） | 执行方式 | 责任/证据 |
|---|---|---|---|
| A1 未实名不能收发付费消息 | `canUsePaidMessaging` 返回 `REALNAME_REQUIRED` | CUSTOM（A-REALNAME） | 后端 / 报告+审计 |
| A2 明文不落库 | 存储/日志/审计无证件明文（只有 hash+尾号） | MANUAL（需文件/日志检查） | 安全 / 检索记录 |
| A3 OTP 单次有效 | 二次用码 `OTP_INVALID`、过期为 `OTP_EXPIRED` | MANUAL（真实短信到达/取码） | 后端 / 短信回执+审计 |
| A4 余额不为负 | 扣费不足 `INSUFFICIENT_FUNDS`，余额不变 | CUSTOM（A-WALLET） | 后端 / 报告 |
| A5 同消息只扣一次 | 账本只 1 条 CHARGE（`pay:<messageId>`） | CUSTOM（A-IDEMP） | 后端 / 报告+账本 |
| A6 已回复不可退 | `REFUND_WINDOW_CLOSED` | CUSTOM（A-REFUND） | 后端 / 报告 |
| A7 日上限生效 | `DAILY_CAP_EXCEEDED`，次日恢复 | CUSTOM（A-CAP） | 后端 / 报告 |
| A8 SUSPENDED 阻断 | 封禁后写操作被阻断 | CUSTOM（A-SUSPEND） | 安全 / 报告+审计 |

## 4. 预检与执行器用法

### 4.1 命令契约（与 `scripts/accept.mjs` 实际实现对齐）

```powershell
# 一条命令：先预检（只读），通过后跑默认 Gate，最后归档报告
node scripts/accept.mjs --target https://im.example.com --token $env:ADMIN_TOKEN `
  --viewer-token $env:VIEWER_TOKEN --require-real-providers --report-dir reports

# 只跑部分 Gate（预检仍会先跑；不过不执行）
node scripts/accept.mjs --target https://<host> --token $env:ADMIN_TOKEN --only G-METRICS,G-BACKUP

# 内测/本机允许内存存储时（正式验收禁止）
node scripts/accept.mjs --target http://127.0.0.1:8080 --token dev-token --allow-memory
```

**CLI 事实（以当前脚本为准）**：参数为 `--target/--token/--viewer-token/--require-real-providers/--allow-memory/--only/--report-dir`；**没有 `preflight`/`run` 子命令**——预检是第一步，失败即 `exit 1` 且不跑 Gate。命令契约只约定语义；若脚本参数变化，以 `node scripts/accept.mjs --help` 或源码为准。

### 4.2 预检判定（§45，只读）

- 可达：目标非 200/不可达 → `ok:false`；
- 鉴权三态：无 token→401、错 token→401、对 token→200，任一不符 → `AUTH_FAILED`；
- `STORE=memory` 且 `expectDurable` → `STORE_NOT_DURABLE`；
- `requireRealProviders` 时 `/api/sms` 主通道仍是 `dev` → `PROVIDER_NOT_CONFIGURED`；
- `Date` 偏移 >5 分钟 → `CLOCK_SKEW`；
- TLS 不安全 → `TLS_INSECURE`；
- Node 主版本 < `minNodeMajor`（默认 22）→ `NODE_TOO_OLD`。

### 4.3 执行器输出与报告

| 字段 | 含义 | 归档要求 |
|---|---|---|
| `ok` | 无 FAIL 才为 true（SKIP/MANUAL 不影响） | 必须 |
| `target` | 验收目标 | 必须 |
| `startedAt/finishedAt` | 起止时间 | 必须 |
| `results[].id/name/tier/status/detail/ms` | 每条 Gate 明细 | 必须 |
| `summary{pass,fail,skip,manual}` | 汇总 | 必须 |
| 副作用 | 只有 `G-BACKUP` 会在目标上创建备份；报告必须标注 | 必须 |

**退出码（与脚本一致）**：`0` = 预检通过且无 FAIL；`1` = 有 FAIL 或预检拦截（未跑 Gate）；`2` = 参数错误。SKIP/MANUAL 不改变退出码，但 **Go/No-Go 必须看人工签**。

### 4.4 归档路径与保留期（⚠ 需复核）

- 路径：`--report-dir reports`（默认）→ `reports/acceptance-<ISO时间戳>.json` + `.md`（人读摘要）；
- 签字表与证据清单建议同目录另放 `signoff-<stamp>.md` 与 `evidence/`；
- 保留：**建议 ≥90 天**（发布/审计追溯；⚠ 法务与留存口径）；
- 归档后不再修改；补测另建报告并引用原报告。

### 4.5 报告关键字段示例（归档核对用）

```json
{
  "target": "https://im.example.com",
  "startedAt": "2026-10-21T10:00:00.000Z",
  "preflight": { "ok": true, "checks": [{ "id": "TARGET", "ok": true, "severity": "PASS" }] },
  "report": {
    "ok": true,
    "finishedAt": "2026-10-21T10:03:12.000Z",
    "results": [{ "id": "G-METRICS", "status": "PASS", "ms": 42, "detail": "funnel ok" }],
    "summary": { "pass": 8, "fail": 0, "skip": 1, "manual": 0 }
  }
}
```

> 归档时核对：`preflight.ok`、`report.ok`、`summary.fail=0`、`SKIP` 是否有原因、`G-BACKUP` 副作用是否标注。

## 5. 真实环境特有风险

| 风险 | 具体表现 | 处置 |
|---|---|---|
| 证书/域名 | 证书链不全、过期、域名不匹配；HSTS 缺失 | `TLS_INSECURE`；预检先验；证书到期告警 |
| 时钟偏移 | 目标与客户端时差 >5min → OTP/审计时间全乱 | `CLOCK_SKEW`；NTP 校准；反代不改 `Date` |
| 反代 XFF | 限流/审计拿到的是反代 IP，误判/绕过 | 配 `TRUST_PROXY`；验收检查 XFF 头 |
| 端口暴露 | 管理面/调试端口直连公网 | 只暴露 80/443；验收 Nmap 抽查 |
| 存储持久 | 容器重建后 `jsonfile` 丢失（看起来“正常”） | `STORE_NOT_DURABLE` 预检；挂持久卷 |
| 短信模板报备 | 模板未审核 → 真实用户收不到 | 上线前完成报备（⚠ 供应商/监管） |
| 机审供应商差异 | 真实阈值/误杀与 mock 不同 | 用真实内容跑基线；误杀率复核 |
| 真实用户数据 | 测试数据混入生产/真实用户进测试库 | 只用测试账号；验收后清理并留审计 |

### 5.9 验收后数据清理清单

| 项 | 动作 | 证据 |
|---|---|---|
| 测试账号 | 封禁/删除（或标注 `test:` 前缀） | 清理记录 |
| 测试付费消息/账本 | 不删账本；测试单标注/归档 | 对账清单 |
| 上传/截图中的 PII | 删除或脱敏后再归档 | 脱敏记录 |
| 真实用户数据 | 不得进入测试库；如误入→按事件处理 | 事件单 |
| 报告中的敏感信息 | token 打码、手机号掩码 | 归档检查 |

## 6. 验收当日流程与 Go/No-Go

### 6.1 T-1（前一天）

1. 部署冻结（不再合入改动）；
2. 跑预检，修 `TARGET_UNREACHABLE/AUTH_FAILED/STORE_NOT_DURABLE/CLOCK_SKEW/TLS_INSECURE`；
3. 创建并 `verify` 一份备份；确认恢复演练脚本可用；
4. 确认真实依赖可用（短信/实名/机审/支付账号）；
5. 分发本 Runbook 与签字表。

### 6.2 T0（当天）

1. 再跑一次预检（只读），记录输出；
2. 跑执行器（当前 CLI 注册默认 Gate），保存报告；
3. 处理 FAIL：修完重跑**该 Gate**并引用新报告；**不允许**改代码后不重跑就宣布通过；
4. 收集 `MANUAL` 证据并签字（**31 条**，见 §3.1）；
5. 判定 Go/No-Go（见下）。

### 6.3 T+1（次日）

1. 归档报告（JSON/MD/签字表/证据）；
2. 复盘：FAIL 与 SKIP 的原因、哪些 Gate 应转自动化（自定义 Gate 待办）；
3. 更新本 Runbook 与阈值；更新 `MANUAL` 清单。

### 6.4 Go / No-Go 判定

| 条件 | Go | No-Go |
|---|---|---|
| 预检 | 7 项全 ok | 任一失败 |
| 执行器 | `ok=true`（无 FAIL） | 任一 FAIL |
| MANUAL | **31 条**全部签字+证据（含 15 条待自定义 Gate） | 任一条未签/无证据 |
| SKIP | 有原因、有 owner、有补测计划 | 无解释的 SKIP |
| 环境 | 证书/时钟/存储/端口/依赖均通过 | 任一不通过 |
| 数据 | 测试数据已隔离/清理方案就绪 | 真实用户数据混入测试 |

> **只有同时满足才 Go**。`ok=true` 不等于 Go——**MANUAL 未签一样 No-Go**。

### 6.5 失败处置决策树

1. **预检失败** → 修环境，**不跑 Gate**；修完重跑预检，记录新输出。
2. **Gate FAIL** → 判断是环境问题还是代码问题：环境问题修完重跑该 Gate；代码问题→冻结发布、修复后**全量重跑**（不允许只跑单条就宣布通过）。
3. **SKIP** → 补凭证（如 `VIEWER_TOKEN`）后重跑；无法补→有 owner 与补测日期，否则 No-Go。
4. **MANUAL 未签** → 补证据再签；不得“先 Go 后补签”。
5. **归档后发现问题** → 不改旧报告，补测另建报告并引用；Go/No-Go 以最新报告为准。

## 7. 一页速查（验收当天打印）

### 7.1 命令

```powershell
node scripts/accept.mjs --target https://<host> --token $env:ADMIN_TOKEN --viewer-token $env:VIEWER_TOKEN --require-real-providers --report-dir reports
```

### 7.2 检查顺序（30 秒）

1. 预检 7 项全 ok？→ 否则修，不跑 Gate。
2. 报告 `ok=true`？→ 否则看 FAIL。
3. `MANUAL` **31 条**签了吗？→ 没签 = No-Go。
4. `SKIP` 有原因/owner 吗？→ 没有 = No-Go。
5. Go/No-Go 表逐项勾。

### 7.3 `MANUAL` 必签清单（31 条）

- **A**：A1、A2、A3、A4、A5、A6、A7、A8
- **B**：B1、B2、B3、B4、B5、B6、B7
- **C**：C1、C2、C3、C4、C5、C6
- **D**：D2、D3、D4、D5、D6（D1 已自动）
- **E**：E1、E2、E3、E5、E6（E4 已自动）

> 其中 15 条未来可注册自定义 Gate 自动化；实现前仍按人工签。

### 7.4 预检失败码速查

`TARGET_UNREACHABLE`（连不上）/ `AUTH_FAILED`（鉴权三态不符）/ `NODE_TOO_OLD`（<22）/ `STORE_NOT_DURABLE`（memory）/ `PROVIDER_NOT_CONFIGURED`（仍 dev）/ `CLOCK_SKEW`（>5min）/ `TLS_INSECURE`（证书/协议）。

### 7.5 三条红线

1. **预检不过，不跑 Gate**（跑了也是噪音）。
2. **MANUAL 不许口头通过**（必须签字+证据）。
3. **报告归档后不改**（补测另建目录）。
