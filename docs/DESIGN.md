# IM2A 设计方案 v0.1

> 产品与交互设计：把「每个人都像大老板一样，有管家/秘书/子 Agent 团队」落到可运行的 IM 里。
> 本文只写设计判断与状态机；接口与模块不变量见 [技术方案](ARCHITECTURE.md)。

## 1. 用户与 Agent 层级

```
用户（人）
└─ 总 Agent（管家）：第一界面、路由、汇总、最终呈报
   ├─ 子 Agent：日程 / 邮件 / 采购 / 家庭事务 / 陌生人过滤（每个单一领域闭环）
   │  └─ Skill：只读能力（日程建议、邮件摘要、比价）→ 需要执行的动作必须走审批
   └─ 记忆：会话上下文 + 用户偏好（v0.1 为会话记忆；v0.2 接分层记忆）
```

**产品原则**
1. 人只做两类事：**最终审批**与**情感沟通**；其余协调由 Agent 完成。
2. Agent 的「自主」必须有边界：能读的不一定能在没有授权时替用户承诺/花钱。
3. 任何 Agent 对外的输出都视同「替用户说话」，必须过出口护栏并留审计。

## 2. 熟人五档信任矩阵

| 档位 | 关系 | Agent 可自主 | 需要人审批 | 禁止 |
|---|---|---|---|---|
| L0 本人 | 自己 | 全部（受预算约束） | — | — |
| L1 家庭 | 配偶/父母/子女 | 日程协调、家庭采购、物业事务 | 大额支出、对外承诺 | 查看工作 Agent 隐私 |
| L2 信任 | 密友/长期同事 | 预约、留言转达 | 涉及第三方信息 | 查看家庭事务 |
| L3 已知 | 普通熟人/校友 | 接收留言并摘要 | 所有对外回复 | 主动发起联系 |
| L4 陌生 | 无关系 | 仅接收结构化来意 | 付费后查看原始消息 | 任何自主执行 |

实现：`services/orchestrator/trust-zone.mjs`（矩阵 + 过期回落）+ `capability-gate.mjs`（代码层判定）。

## 3. 审批流（人机混合的核心）

```
Agent 发现需要人决策
  → 生成审批单（发起 Agent / 事项 / 金额或风险 / 建议动作 / 截止时间）
  → 进入「审批态」列表（默认首页）
  → 人：通过 / 修改 / 驳回
      ├─ 通过 → 执行（扣费/下单/回复）→ 事件溯源 → 审计链
      ├─ 修改 → 以人的修改为准执行（Agent 只是预拟稿）
      └─ 驳回 → 执行链终止；陌生人场景对方不被扣费
```

**UX 硬约束**：一张卡 30 秒内可完成决策；卡面不出现 Agent 的内部推理长文，只给结论与风险。

## 4. 陌生人付费消息

```
陌生人 Agent → 目标用户 Agent：结构化来意（谁/为什么/期望/紧急度/付费模式）
  → 目标 Agent 按用户预设规则预审（PASS/REVIEW/BLOCK）
      ├─ BLOCK → 拒绝，不打扰人
      └─ PASS → 生成审批卡（含计费模式与金额）
            ├─ 人驳回 → 不扣费
            └─ 人通过 → 扣费 → 查看 → 回复 → 结算
                  └─ 信任升 L3「已知」；对方后续可留言但不能查看家庭事务
```

两档计费：**发送即扣费**（过滤批量垃圾）/ **看到且回复才扣费**（高价值人脉）。
不变式：**付费永远发生在 Agent 预审之后**，付费不能替代预审。

状态机（`services/payment/paid-message.mjs`）：
`INTENT → AWAITING_PAYMENT → PAID → VIEWED → REPLIED → SETTLED`，异常分支 `REFUSED / REFUNDED / EXPIRED`。

## 5. Agent Runtime 循环（模型只「想」，系统「做」）

```
1) 规划：模型输出 JSON {intent, tool, args}（离线时用确定性规则）
2) 门控：Agent 声明白名单 ∧ 信任档位 ∧ 参数校验 → 允许/拒绝（具名原因）
3) 执行：Skill Executor（v0.1 本地；v0.2 可换 MCP 适配器）
4) 起草：模型基于工具结果写回复；失败回落工具结果摘要
5) 护栏：EgressGuard 过审，BLOCK 内容不进入会话
6) 审计：一次调用一条记录（tool/deny/reply）
```

## 6. 客户端交互（浏览器 Demo）

- **登录态**：未启用鉴权时直接进入；启用后登录浮层 + 登出；身份来自会话，界面不再允许切身份冒充。
- **IM 布局**：左会话列表 / 中消息流 / 右 Agent 与审批面板。
- **审批态**：默认高亮待审批；Agent 消息带来源徽标（`LLM xxms` / `离线模板` / Skill 名）。
- **状态可见**：Agent Runtime 卡片（轮次/Skill 调用/拒绝数/目录）、LLM 卡片（模式/模型/调用/token/延迟）、审计链卡片（链完整性/长度/head）。
- **移动端**：v0.1 桌面优先；响应式断点后为单列（后续做）。

## 7. 数据模型（SQLite v0.1）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `threads` | id, kind, title, members_json | 会话元数据（家庭/陌生人/Agent 频道） |
| `messages` | id, thread_id, at, sender, text, kind, engine_json, ticket_id | 消息；engine 记录模型/Skill 元数据 |
| `audit` | seq, at, source, action, actor, trace_id, target, decision, detail_json, prev_hash, hash | 哈希链 |
| `meta` | key, value | 消息序号等 |

生产迁移（v0.3）：PostgreSQL + 只追加审计表 + 分区；DDL 设计在此冻结前先评审。

## 8. API（v0.1）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/session` | 会话状态与可登录账号 |
| POST | `/api/login` / `/api/logout` | 登录/登出（Cookie 会话） |
| GET | `/api/state?thread=` | 会话列表 + 当前会话 + 审批单 + Agent + 信任矩阵 + 审计链 + Runtime/LLM 状态 |
| POST | `/api/message` | 发消息（身份来自会话；陌生人锁定时拒绝） |
| POST | `/api/approvals/{id}/decide` | 通过/修改/驳回（只能处理名下审批单） |
| GET | `/api/runtime` | Agent Runtime 统计与 Skill 目录 |
| GET | `/api/llm` | 大模型引擎状态 |
| POST | `/api/reset` | 重置演示世界 |

## 9. 设计上明确「不做」的事

- 不做「Agent 自动替用户承诺时间/金额」：需要对外承诺的动作必须审批。
- 不做「全自动合并」：冲突只提示下一步（重读→比对→按当前版本追加）。
- 不做「模型自行调用工具」：模型只能产出计划，执行经代码层门控。
- 不在 v0.1 做硬件与端侧模型：保留 BLE/SDK 接口设计，不承诺首发。
