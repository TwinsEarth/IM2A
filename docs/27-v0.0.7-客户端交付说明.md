## 1. 版本定义

### 1.1 解决「客户端只存在于未编译代码里」

| 现状（v0.0.6） | v0.0.7 |
|---|---|
| `client/` 是 Flutter 代码，**未编译、未真机跑**（`client/README.md` 明说） | 交付一个**浏览器就能打开**的客户端，PC/手机同一份 |
| 审批/账本只能在终端或旧页面看 | **三态导航**：审批 / 巡视 / 账本，连真实 HTTP 接口 |
| “客户端没问题”只能靠口头 | `logic.mjs` 纯函数可被 **Node 测试**直接导入；页面可被人工/自动化打开验证 |
| PWA/离线未讨论 | manifest + Service Worker：离线给壳、版本可更新 |

### 1.2 交付物清单（契约 §47 冻结路径）

| 文件 | 职责 | 关键约束 |
|---|---|---|
| `apps/im2agent/public/app/index.html` | 三态导航 shell | 不内联敏感数据；可被静态服务 |
| `apps/im2agent/public/app/app.js` | 视图层 | **只依赖 `logic.mjs` + `fetch`**，不引第三方库 |
| `apps/im2agent/public/app/logic.mjs` | 纯函数 | **无 DOM、无网络**，浏览器与 Node 共同导入 |
| `apps/im2agent/public/app/app.css` | 样式 | 深色、移动优先 |
| `apps/im2agent/public/app/manifest.webmanifest` | PWA 清单 | `name/short_name/display/theme_color/icons` |
| `apps/im2agent/public/app/sw.js` | Service Worker | 离线壳 + 网络优先数据 |

**`logic.mjs` 冻结导出（逐字）**：

```js
export function formatCents(cents);        // 5000 -> '¥50.00'；非法输入 -> '—'
export function summarizeTickets(state);   // -> { pending, pendingHigh, done }
export function canDecide(role);           // operator -> true；viewer/未知 -> false
export function moderationQueue(state);    // -> HUMAN_PENDING 案件列表（巡视态用）
export function funnelSummary(metrics);    // -> [{stage,count,rate}]；缺数据不抛
```

### 1.3 不是什么

- **不是 Flutter 编译产物**：没有 APK/IPA/EXE，Flutter 仍是「未编译等价物」；
- **不是应用商店版本**：不上架、不做签名分发；
- **不是原生能力客户端**：推送/手表/BLE/相机不承诺（见 §7.2）；
- **不是管理后台的替代**：Web/PWA 面向内测用户的审批/巡视/账本，不替代 `admin.html` 的运维全量视图。

## 2. 形态与能力矩阵

### 2.1 Web/PWA vs Flutter 三端

| 维度 | Web/PWA（v0.0.7，✅ 可验证） | Flutter 三端（⚠ 未编译） |
|---|---|---|
| 打开方式 | 浏览器访问 `/app/`；可“添加到主屏幕” | 需 Flutter SDK 编译后安装 |
| 三态导航 | **审批 / 巡视 / 账本**（§47） | 现有代码是**审批 / 账本 / 审计**三 Tab（与 Web 不完全一致，见 §7.1） |
| 数据来源 | 真实 HTTP（`/api/*`）+ SSE（可用时） | 真实 HTTP（`/api/admin/state` 等） |
| 离线 | Service Worker 壳 + 网络优先 | 无本地持久化（token 重启需重输） |
| 推送 | 不承诺（浏览器/平台差异大，⚠ 需复核） | 未实现（`client/README.md` 已知边界） |
| 编译/真机验证 | 浏览器打开即可 | **未做**：无 Flutter SDK/真机/签名 |
| 状态 | ✅ 可验证 | ⚠ 未编译，只能作“代码对齐参考” |

### 2.2 端上能做什么 / 不能做什么

| 能做（Web/PWA） | 不能做（v0.0.7 明确不做） |
|---|---|
| 看审批卡片、通过/驳回（operator） | 语音审批、生物识别 |
| 看巡视态：Agent 列表、审核队列、熔断状态、指标摘要 | 修改阈值/规则（只读展示；修改走运维后台） |
| 看账本：余额、流水、退款入口分流 | 真实支付/提现（体验额度，不是真实资金） |
| PWA 离线壳、失败重试、空态提示 | 后台常驻推送、离线写操作（离线只读） |
| 手动刷新 + SSE 自动更新（可用时） | 承诺“实时必达” |

### 2.3 PWA 离线边界与 SSE 可用性

- **离线只给壳**：网络断开时显示“当前离线/稍后重试”，不展示旧余额/旧审批（避免“看起来是最新”的危险）；
- **不缓存敏感内容**：`/api/*` 响应、token、审批正文不进 Cache Storage；
- **SSE**：`/api/events` 可用时自动刷新；不可用/断线时退化为手动刷新 + 明确提示（文案只写“SSE 可用时自动更新”，不写“实时推送”）；
- **多端一致性**：不做离线写；写操作必须在线且服务端确认成功后才更新 UI。

### 2.4 页面结构与路由（轻量 hash 路由，无框架）

| 路由 | 视图 | 说明 |
|---|---|---|
| `/app/#approval` | 审批 | 默认页；卡片列表 + 动作 |
| `/app/#oversight` | 巡视 | Agent/审核队列/熔断/指标 |
| `/app/#ledger` | 账本 | 余额/流水/退款入口 |
| `/app/#login`（或只读态） | 角色/登录 | viewer 可跳过；operator 需 token |

> 路由只做**视图切换**，不做权限判定；权限在服务端。刷新后保持当前 Tab（hash），不把 token 放 URL。

## 3. 三态交互设计

### 3.1 审批态

| 区块 | 字段（来源） | 空态 | 错误态 |
|---|---|---|---|
| 待审批列表 | `tickets[]`（`GET /api/state` 或 admin 会话接口） | “暂无待审批” | 拉取失败 → “加载失败，点击重试” |
| 卡片 | 类型/金额/来意摘要/预审结论/计费模式 | 字段缺失 → 显示“—”，不猜 | 解析失败 → 卡片降级为最小信息 |
| 动作 | 通过/驳回（`canDecide(role)` 为 true 才渲染） | viewer → 按钮不渲染，显示“只读” | 409 `ILLEGAL_TRANSITION` → 提示已处理并刷新 |
| 待审说明 | 为什么需要人审（机审 `FLAG`/金额阈值/陌生人） | 无说明 → “见详情” | 无权限 → 不展示原因 |

### 3.2 巡视态

| 区块 | 字段（来源） | 空态 | 错误态 |
|---|---|---|---|
| Agent 列表 | agentId/状态/在线（`logic` 展示层；数据来自接口） | “暂无 Agent” | 接口未接入 → “未接入”，**不伪造** |
| 审核队列 | `moderationQueue(state)` → `HUMAN_PENDING` 案件 | “队列为空” | 拉取失败 → “审核服务不可用” + 重试 |
| 熔断状态 | provider `CLOSED/OPEN/HALF_OPEN`（接口/指标） | “未接入” | 状态未知 → 显示“未知”，不显示绿色 |
| 指标摘要 | `funnelSummary(metrics)`：六段计数/转化 | 无数据 → 全 0 并注明“无数据” | NaN/缺失 → `logic` 返回 0 而非 NaN |

### 3.3 账本态

| 区块 | 字段（来源） | 空态 | 错误态 |
|---|---|---|---|
| 余额 | `availableCents/frozenCents`（钱包/账本接口） | 0 元 | 失败 → “余额加载失败”，不显示 0 冒充 |
| 流水 | 账本条目（`CHARGE/REFUND/DEPOSIT`） | “暂无流水” | 失败 → 重试；不拼接本地缓存 |
| 退款入口 | 未回复 → 自助退（§37）；已回复 → 争议（§39） | 不符合 → 按钮置灰并说明 | 服务端未暴露接口 → 提示“联系客服”，**不伪造成功** |

> 三态共同规则：**空态/错误态必须可区分**（“没有数据”≠“加载失败”≠“无权限”）；错误文案不暴露内部字段。

### 3.4 空态 / 错误态 / 无权限：三分法

| 状态 | 触发 | 展示 | 动作 |
|---|---|---|---|
| **空态** | 接口 200，数据为空 | “暂无待审批/流水/Agent” | 刷新；不显示“错误” |
| **错误态** | 网络失败/5xx/解析失败 | “加载失败，点击重试”（不展示旧数据） | 重试；连续失败提示联系客服 |
| **无权限** | 401/403 | “只读账号/无权限查看” | 引导登录或联系管理员；**不伪装成空态** |

> 三者混用是客户端最常见的信任问题：把 403 显示成“暂无数据”，用户会以为“真的没有”。

## 4. 角色与安全

### 4.1 `viewer` / `operator`

| 角色 | 能看 | 能写 | 前端 | 服务端 |
|---|---|---|---|---|
| `viewer` | 审批/巡视/账本只读 | ❌ | 不渲染写按钮 | 写请求 → 403 `FORBIDDEN_ROLE` |
| `operator` | 同上 | 审批通过/驳回等 | 渲染按钮 | 二次校验角色与权限 |
| 未知角色 | 不渲染写操作 | ❌ | `canDecide(unknown) === false` | 401/403 |

### 4.2 token 存储与登出

| 项 | 规则 |
|---|---|
| 存储位置 | **`sessionStorage` / 内存**；不写 `localStorage` 长期保存，不放 URL query |
| 作用域 | admin token 仅 operator 会话使用；**不得当用户态**（契约 §47 不变量①） |
| 登出 | 清 token + 清页面状态 + 断开 SSE；返回登录/只读态 |
| 过期 | 服务端 `SESSION_EXPIRED` → 跳到登录/只读，不静默续期 |
| 泄露防护 | 不在 DOM/日志/截图提示里回显 token；报告/验收记录中打码 |

### 4.3 前端隐藏 ≠ 安全（双保险）

- `canDecide(role)` 只决定**按钮是否渲染**；它不是权限判定；
- 所有写操作由服务端**二次校验**（角色 + token + 业务状态）；
- 反例：改前端 JS 强行显示按钮 → 服务端仍 403；这正是验收 F3 要测的。

### 4.4 token 泄露/截图/日志处置

| 场景 | 处置 |
|---|---|
| 误把 token 贴进聊天/工单 | 立即吊销（服务端）、换新 token、留审计 |
| 截图含 token/手机号 | 打码后归档；原图删除 |
| 日志/报告 | token 打码；不记录完整 `Authorization` 头 |
| 共享电脑 | 用 `sessionStorage` + 关闭标签即清；提供显式“退出”按钮 |

## 5. PWA 与离线

### 5.1 manifest 关键字段

| 字段 | 要求 |
|---|---|
| `name` / `short_name` | 产品名/短名（不夸大能力） |
| `display` | `standalone`（像应用一样打开） |
| `theme_color` / `background_color` | 与深色 UI 一致 |
| `icons` | 至少 192/512（⚠ 缺图标不 block 验收，但安装体验差） |
| `start_url` | `/app/` |

### 5.2 Service Worker 缓存策略

| 资源 | 策略 | 理由 |
|---|---|---|
| 壳（HTML/CSS/JS/manifest/图标） | cache-first + 版本更新 | 离线可打开，不白屏 |
| `/api/*` 数据 | **不缓存**（或 network-only） | 余额/审批/账本必须实时；缓存会误导 |
| token/凭据 | **绝不缓存** | 安全 |
| 图片/静态资源 | stale-while-revalidate | 体验与一致性折中 |

### 5.3 更新提示与版本

- `sw.js` 版本号变更 → 新 SW 安装；页面提示“有新版本，刷新后生效”；
- **不静默强刷**：避免用户正在填审批意见时被刷新；
- 回滚：保留上一版本静态资源路径（简单 hash/目录），出问题可回退。

### 5.4 离线验收步骤（DevTools）

1. 正常打开 `/app/`，确认 SW 已注册（Application → Service Workers）。
2. DevTools → Network 勾选 **Offline**（或断 Wi-Fi），刷新 `/app/`：**必须显示离线壳**，不白屏。
3. Application → Cache Storage 检查：**不得出现 `/api/*` 响应、token、审批正文**。
4. 恢复网络：页面可重试/自动恢复；提示“已恢复联网”。
5. 更新 SW 版本：出现“有新版本”提示，刷新后生效（不静默强刷）。

## 6. 验收 Gate F1–F5

| # | 验收项 | 判定标准（可执行） | 验证命令 | 本机状态 |
|---|---|---|---|---|
| F1 | **三态导航可用** | `/app/` 可打开；审批/巡视/账本三 Tab 可切换；数据来自真实 HTTP（非 mock） | 浏览器打开 `/app/` + `node scripts/test.mjs --filter=web-client` | ⚠ 实现落地中 |
| F2 | **`logic.mjs` 纯函数** | Node 直接 import：`formatCents(5000)==='¥50.00'`、非法→`'—'`；`canDecide` operator true/viewer false；`summarizeTickets/moderationQueue/funnelSummary` 缺数据不抛、无 NaN | `--filter=web-client` | ✅ 已代码化（3 passed） |
| F3 | **角色门控双保险** | viewer 会话：按钮不渲染；且直接调写接口 → 403 `FORBIDDEN_ROLE`；operator 可写 | 手工切换角色 + 接口直调 | ⚠ 实现落地中 |
| F4 | **PWA 离线壳与不缓存敏感** | manifest 可解析、SW 注册成功；断网打开 `/app/` 显示离线壳不白屏；Cache 中无 `/api/*`/token | DevTools Application + 断网 | ⚠ 实现落地中 |
| F5 | **文案与降级诚实** | 无“实时推送/必达”绝对承诺；SSE 不可用时明确“手动刷新”；空态/错误态/无权限可区分 | 人工走查 + 断 SSE | ⚠ 实现落地中 |

**Gate 规则**：F1–F5 全过才允许把 `/app/` 地址发给内测用户；⚠ 项须有浏览器/手机实测记录（至少 Chrome/Edge + 一台手机）。

**反例（看起来通过的三处）**：

1. **「三态可用」**：只测 Tab 能点不算——必须确认数据来自真实接口且空态/错误态正确。
2. **「角色安全」**：只测按钮隐藏不算——必须直调写接口验证 403。
3. **「PWA 可用」**：只测 manifest 存在不算——必须**断网**验证壳不白屏，且 Cache 无敏感数据。

## 7. Flutter 差距与补齐计划

### 7.1 能力对齐（Web/PWA vs 现有 Flutter 代码）

| 能力 | Web/PWA | Flutter 现有 | 差距/动作 |
|---|---|---|---|
| 审批卡片 + 通过/驳回 | ✅ | ✅（代码） | 对齐字段与错误码 |
| 账本/余额/流水 | ✅ | ✅（账本 Tab） | 对齐退款入口 |
| 巡视（Agent/审核队列/熔断/指标） | ✅ | ❌（只有审计 Tab） | **Flutter 需新增巡视 Tab** |
| 三态命名 | 审批/巡视/账本 | 审批/账本/审计 | 统一口径（审计并入巡视的“证据”区） |
| 角色门控 | `canDecide` + 服务端 | 未做角色切换 | 补齐 viewer/operator |
| PWA/离线 | ✅ | ❌ | Flutter 需本地持久化/离线缓存（后续） |

### 7.2 只有原生才有的能力（Web/PWA 不做承诺）

| 能力 | 为什么 Web/PWA 不承诺 | 归谁 |
|---|---|---|
| 系统推送 | 浏览器/平台差异大（iOS 限制 ⚠ 需复核） | Flutter 原生 + 厂商推送 |
| 手表/可穿戴 | 需要原生 SDK/蓝牙 | Flutter/native（Phase2） |
| BLE/耳机/眼镜 | 硬件协议 | 原生端（Phase2） |
| 相机/扫码 | 权限与体验差异 | 原生端（Phase2） |
| 后台常驻/离线写 | 浏览器沙箱限制 | 原生端/后台服务 |

### 7.3 Flutter 编译验收需要什么

| 目标 | 需要 | 当前 |
|---|---|---|
| Windows | Flutter SDK + Visual Studio 工具链 | ⚠ 无 |
| Android | Flutter SDK + Android SDK/JDK + 签名 | ⚠ 无 |
| iOS | **macOS + Xcode + 签名证书** | ⚠ 无 |
| 真机 | 设备 + 网络（局域网/HTTPS） | ⚠ 无 |
| 结论 | Flutter 保持「未编译等价物」 | 编译验收另立任务（不在 v0.0.7 承诺） |

### 7.4 Flutter 编译验收清单（未来任务，不在本版）

- [ ] iOS：macOS + Xcode + 签名后 `flutter build ipa`；真机可审批。
- [ ] 角色：viewer 只读、operator 可写（对齐 Web 的 `canDecide`）。

- [ ] 不把“未编译”写进对外交付说明——本清单通过前，Flutter 一律标 ⚠。

## 9. 一页速查

### 9.1 给内测用户的三句话

1. **打开哪个地址**：`https://<内测域名>/app/`（手机浏览器也可，选择“添加到主屏幕”更像 App）。
2. **怎么审批**：进“审批”页，看卡片 → 通过/驳回；只读账号看不到按钮是正常的（不是坏了）。
3. **怎么退款**：进“账本”页；对方**没回复**可自助退，**已回复**走“争议”联系客服；余额是体验额度，不可提现。
