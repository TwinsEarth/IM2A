# 10 · 风险与验收登记册

> 文档定位：**活的登记册**。风险条目按编号管理、按月复审；验收矩阵与上线清单用于 Gate 评审与 Go-Live。
> 上游契约：`contracts/INTERFACES.md` v1.0；关联 `docs/06`（硬件）、`docs/07`（交互）、`docs/08`（合规运维）、`docs/09`（计划）。
> 标记：**⚠ 需复核** = 阈值/概率为初始判断，需数据校准。

---

## 1. 登记册使用规则

| 规则 | 内容 |
|---|---|
| 编号 | `R-nn` 只增不改；风险关闭后标 `CLOSED(yyyy-mm-dd)`，不删行 |
| 责任 | 每条只有一个责任人（Owner），可列协办 |
| 复审 | 高危每 2 周、中危每月、低危每季度；Gate 前强制全量复审 |
| 升级 | 等级升到「极高」或触发信号出现 → 24h 内上报 Lead/管理层 |
| 变更 | 新增风险走评审；等级调整需记录原因与依据 |
| 关联 | 关键风险须在 `docs/09` 的 WBS 中有对应缓解工作项 |

| 概率 \ 影响 | 低（体验/局部） | 中（阶段目标/收入） | 高（合规/资金/安全） |

## 4. Top 风险深潜（缓解工作项与预算）

### R-02 付费绕过过滤（最高优先）

| 项 | 内容 |
|---|---|
| 攻击路径 | 付费→期望跳过预审；伪造预审 PASS；批量小额骚扰；退款套利 |
| 技术控制 | `screen()` 是 `pay()` 的前置状态（`INTENT→AWAITING_PAYMENT` 才可付）；`BLOCK→REFUSED` 不可付；`pay` 幂等键 `pay:<messageId>`；日限额；退款仅 `PAID/VIEWED` |
| 运营控制 | 来意卡片必展示预审结论；举报一键；退款率 >20% 自动限流 |
| 验收 | 红队 200 例「BLOCK 后付费」全部失败；渗透报告 0 高危 |
| 预算 | 2 人月 + 风控规则库 |

### R-03 硬件隐私事件

| 项 | 内容 |
|---|---|
| 最坏情形 | 拆解证明固件可关灯录音，或抓包发现原始音频上行 → 品牌级死亡 |
| 技术控制 | P-01~P-05（06 §4）；端侧环形缓冲命中即清；传输事件可自证 |
| 第三方 | 安全审计 + 漏洞赏金 + 公开白皮书（⚠ 预算待定） |
| 预案 | 24h 内 OTA 禁用麦克风并公告；72h 内出根因报告 |
| 验收 | 拆机 + 抓包 + 固件注入测试三重通过 |

### R-09 资质审批延期

| 项 | 内容 |
|---|---|
| 最坏情形 | 硬件已量产但无 ICP 证，付费消息不能开，只剩免费版 → 现金流断裂 |
| 缓解 | 双轨上线（免费版先发）；硬件销售与订阅解耦（先卖硬件）；申报 W2 启动 |
| 决策点 | M6 时若 Q-02 未受理，启动「仅免费 + 预约付费」方案 |
| 验收 | W12 前取得 Q-01、Q-04 受理，W24 前 Q-02 受理 |

### R-05 协商烧推理

| 项 | 内容 |
|---|---|
| 成本模型 | 单会话 token 上限 4000；按模型单价折算单会话成本上限（⚠ 单价需复核） |
| 控制 | `maxRounds/maxTokens/maxSeconds` 三上限；超限 `INPUT_REQUIRED`；同轮去重；跨会话缓存 |
| 告警 | 单用户日成本 >¥3、单会话 >¥0.5 |
| 验收 | 压测 1000 并发会话，成本曲线线性且无爆炸；超限场景 100% 返回 `INPUT_REQUIRED` |

### R-10 蒸馏漂移

| 项 | 内容 |
|---|---|
| 漂移信号 | 自主完成率周环比 +10pp、通过率 >95%、修改率 +10pp |
| 控制 | 校准需样本量 + 双周同向 + 单周 1 次 + 步长 1 档；放开类变更需人工确认；用户可撤销 |
| 回滚 | 保留最近 4 周阈值快照，一键回滚 |
| 验收 | 模拟 8 周校准，无「全自主」或「全审批」两极震荡 |
