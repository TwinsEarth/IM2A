## 一、产品（软硬件形态）

### 1.1 软件形态：一个人的 Agent 团队

```
L0 总管（butler）      路由 / 优先级仲裁 / 跨子 Agent 协调 / 唯一向人呈报的界面
   ├─ L1 工作邮件子 Agent
   ├─ L1 采购比价子 Agent
   ├─ L1 物业/水电煤子 Agent
   ├─ L1 日程预约子 Agent
   ├─ L1 法律 / 教育 / 家政 / 维修 / 亲子子 Agent
   ├─ L1 陌生人过滤子 Agent
   └─ L2 Skill（MCP Server 形态）：比价 API、缴费 API、日历 API、合同检索……
```

三条产品级规则：

1. **总管只持有"协调摘要"**，读不到子 Agent 的原始记忆（`MEMORY_ISOLATED`），避免单点全知。
2. **蒸馏不是改模型权重**：用户的审批/驳回/修改 → 收紧或放宽子 Agent 的自动阈值（`tool-policy` 的 `approvalThresholdCents`）。表现是"管家越来越懂你"，而不是"模型被重训"。
3. **人格文件（SOUL）与记忆分离**：价值观/规则/边界稳定、低频变更且留痕；记忆按 `WORKING→EPISODIC→SEMANTIC` 晋升、会衰减、可遗忘（软删 + tombstone）。

详见 [`docs/11` 宿主型 IM](11-AI原生IM架构-v2.md) 与 [`docs/02` 选型](02-技术选型与框架.md)。

### 1.2 硬件形态：三阶段，不赌单点

| 阶段 | 形态 | 定位 | 关键约束 |
|---|---|---|---|
| Phase1 | **耳夹式耳机**（首发） | 最高频场景是"接电话/听留言/语音审批"，佩戴门槛低于眼镜 | 单次续航 9h + 充电盒 40h；端侧只做唤醒/VAD/敏感过滤 |
| Phase2 | **AI 眼镜**（第二形态） | 第一视角拍摄、翻译、会议记录 | 摄像头/麦克风**物理指示灯 + 物理静音开关**为强制规格 |
| Phase3 | 指环 / 夹子 | 健康监测 + 触觉通知 / 固定衣物采环境音 | 供应链与交互范式未成熟，不作为首发 |

**"24 小时在线"的工程定义**（最容易含糊的一句）：不是单次续航 24h，而是「换电/充电盒覆盖全天 + 待机时只维持 BLE 与本地唤醒词，Agent 在线是云端/手机侧能力」。原始音频**不出设备**；需要上云的语音由用户显式触发，且每次上云产生可审计的传输事件。

详见 [`docs/06` 产品形态与硬件](06-产品形态与硬件.md)。

### 1.3 商业模式（与第 6 条需求绑定）

| 收入 | 设计 | 防止什么 |
|---|---|---|
| 硬件 | 首发定价千元内，绑定 6 个月 Agent 订阅 | 用硬件一次性收入补贴软件，降低尝试门槛 |
| 订阅 | ¥29/月 或 ¥299/年（⚠ 需复核定价） | 覆盖 Agent 运行成本与云端推理 |
| 陌生人付费消息 | 两档：发送即扣费（过滤批量）/ 看到且回复才扣费（高价值触点）；**价格由接收方自设** | 付费**不能**绕过预审——付费买的是"已被对方 Agent 预审过的有效触点"，不是"通行证" |

## 二、技术（框架 & 前后端 & 智能引擎 & 数据库）

### 2.1 六层架构（v2 起，v7 修正底座）

```
L1 接入层     耳夹耳机/眼镜（BLE）· 手机 · PC · 手表 · Web
L2 端侧层     唤醒后 ASR · 意图粗分类 · 敏感前置过滤 · BLE 网关 · 离线审批缓存
L3 通信层     人类 IM：Phase0–1 腾讯云 IM PaaS + §31 适配层；Phase2 评估自托管/WKongAI
              Agent 协商：独立通道（频道类型 AGENT_NEGOTIATION，对人类未读恒 0）
L4 编排层     AgentRegistry · SkillRuntime · CapabilityGate · ApprovalEngine
              NegotiationEngine · 记忆分层 · EgressGuard · AgentGateway · 可信上下文 · 委托
L5 模型层     端侧小模型（唤醒/意图/过滤，守门人）↔ 云端大模型（规划/协商/专业推理）
              敏感域（家庭/法律/医疗/记忆）钉本地模型
L6 数据层     PostgreSQL（关系链/信任/账本/审批/协商）· pgvector（记忆）
              对象存储 + OpenSearch（归档检索）· Kafka（治理事件）· 不可变审计
```

**三条流量必须分离**：人类 IM 消息 / Agent 协商 / 审批与审计事件。混在一起的后果是"协商中间态污染人类未读，且无法细粒度审计"。

### 2.2 后端框架与关键模块

| 层 | 生产选型 | 本仓库参考实现（可跑） |
|---|---|---|
| 语言/框架 | Go + Go-Zero（gRPC/Protobuf/etcd） | Node 22 零依赖 ESM（语义等价） |
| 通信 | gRPC 内部 + PaaS 长连接 | `services/messaging/*`（envelope/seq/channel/session/mailbox/adapter） |
| 编排 | 自研（不引入 Temporal，Phase0–2） | `services/orchestrator/*`（11 个模块） |
| 身份/网关 | Ed25519 + AgentCard + AgentGateway | `services/identity`、`services/gateway` |
| 资金 | PostgreSQL 事务 + 唯一索引 | `services/payment`（ledger 幂等） |
| 审计 | 哈希链 + 签名 + WORM | `services/audit`（AuditLog + SignedAuditLog） |

### 2.3 智能引擎：三处"AI 出现的位置"，三套不同的约束

| 位置 | 职责 | 铁律 |
|---|---|---|
| **端侧小模型** | 唤醒、VAD、意图粗分类、敏感前置过滤 | 不持续上传原始音频；不做完整 Agent（功耗+隐私双陷阱） |
| **云端大模型** | 协商、多步规划、专业推理、起草回复 | **只起草**：不调用 Skill、不扣费、不审批；失败必须降级且标 `degraded` |
| **本地/端侧模型** | 家庭、法律、医疗、记忆等敏感域 | 敏感域**不出端侧**（`model-router`） |

LLM 三档降级：`template → fallback → real`。无 key 走模板；上游失败回落模板并**明确标记已降级**；成功才 `real`。压测证据：200 次调用、30% 上游失败 → `fallback 62 / real 138 / 异常穿透 0`。

### 2.4 数据库与数据模型

| 数据域 | 选型 | 关键约束 |
|---|---|---|
| 关系链 / 五档信任 / 能力声明 | PostgreSQL | 强一致；授权过期即撤销；变更全审计 |
| 审批单 / 协商会话 | PostgreSQL | 长生命周期、可寻址、超时升级；状态机白名单 |
| 付费消息 + 账本 | PostgreSQL | 账本**只 INSERT**，`idempotency_key` 唯一索引实现"恰好一次" |
| Agent 记忆 | pgvector（→ Milvus 迁移阈值） | 按 `agent_id` 隔离；`MEMORY` 域永不返回原始内容给其他 Agent |
| 归档与检索 | 对象存储 + OpenSearch | 满足审核回溯与监管调取 |
| 审计 | 不可变存储 + 签名链 | 每一跳可验；v1 历史用 CHAIN_ANCHOR 接续 |

完整 DDL 见 [`docs/05` 数据模型](05-数据模型与存储.md)（12 张核心表 + 8 张 v2/v6 表）。

## 三、客户端 & UI 交互

### 3.1 双态范式（这是产品差异点，不是"又一个聊天界面"）

| 态 | 内容 | 设计目标 |
|---|---|---|
| **审批态**（默认） | Agent 团队呈报的待决策事项，按紧急/重要排序；每张卡片含"哪个子 Agent / 做了什么 / 建议动作 / 涉及信任档 / 金额或对象 / 风险 / 通过·修改·驳回" | **30 秒完成一次有效决策** |
| **巡视态** | 子 Agent 在干什么：协商轮次、调用链、记忆摘要、异常告警、执行中任务 | 让"像看团队工作"而不是"翻聊天记录" |

### 3.2 四个关键界面细节

1. **陌生人「来意卡片」**：陌生人消息**不直接进会话列表**，先进入过滤队列，显示结构化来意 + 双方 Agent 协商摘要 + 计费模式与金额。用户"忽略"（不扣费）或"接受并查看"（触发扣费）。**付费决策与注意力保护合并成一个动作**。
2. **第三人称转达**：Agent 进入人类会话只能以 `AGENT_SUMMARY / notFromHuman=true` 的形式出现，**不得冒充任何一方**（`IMPERSONATION_BLOCKED`）。
3. **手表三屏**：审批卡片（是/否/稍后）、未读摘要、紧急联系人一键触发。手表是**决策端**，不是浏览端。
4. **语音审批的安全约束**：语音可以"听摘要、说通过"，但涉及资金/第三方承诺时必须二次确认（屏幕或按键），**审批不可只靠语音**。

### 3.3 客户端技术栈与现状

- **生产**：Flutter（手机/PC/手表同一份业务逻辑），硬件走 BLE（LC3）由手机 App 作网关。
- **本仓库**：`client/`（Flutter 三态导航：审批/账本/审计）⚠ **未编译**；`apps/im-live/public/*`（网页端）✅ 可跑。

详见 [`docs/07` 客户端与 UI](07-客户端与UI交互.md) 与 [`client/README.md`](../client/README.md)。

## 四、运营、客服与运维（含合规）

| 板块 | 关键设计 | 现状 |
|---|---|---|
| 资质 | ICP 经营许可（≥100 万）、国内多方通信（全网≥1000 万/地网≥100 万）、等保三级、实名 | ⛔ 纸质流程，代码不涉及 |
| 内容审核闭环 | 机审 → 人审 → 申诉 → 处罚；所有 Agent 外发内容（含 Agent 间协商摘要）必须过出口护栏 | ✅ `egress-guard`（规则层）；⚠ 机审 API 未接 |

| 分层客服 | L1 机器人（连接/计费/权限）→ L2 人工（退款/隐私/封号，24h 首响）→ L3 安全合规（审核申诉/执法/未成年人，7×24） | 设计（`docs/08`） |

## 五、落地节奏（与真实 tag 对齐）

```
Phase0（M1–M4）  合规先行 + 最小 Agent 闭环（手机/PC）        → 完成 = 审批态周活 ≥40%、单次决策中位 ≤30s
Phase1（M5–M9）  付费消息 + 熟人五档 + 耳夹耳机首发            → 完成 = 预审拦截率 ≥95%、硬件退货率 <8%
Phase2（M10–M18）子 Agent 扩展 + AI 眼镜 + 蒸馏管道            → 完成 = 越权 Skill 拦截 100%、协商完成率 ≥90%
Phase3（M18+）   A2A 边界 + Skill 生态 + 个人 Agent 操作层
```

**本仓库已经走过的那一段**（可作为 Phase0 的技术验证）：

```
v0.0.1-demo → v0.2.0-linux → v0.2.1-admin → v0.3.0-client → v0.4.0-lan
→ v0.5.0-llm → v0.6.1-prod → v0.7.0-contract → v1.0.0-baseline → v0.8.0-ops
```

> 注意顺序：这里的 tag 是**技术形态**的演进（先跑通链路、再上大模型、再部署），
> 而 Phase 是**产品阶段**。两者不是同一个轴，别拿 tag 当交付节点对外承诺。

### 6.3 三个待你拍板的决策

1. **底座**：维持 v7 的「Phase0–1 PaaS + 适配层」还是回到自托管内核？（影响 §31 的 8 条补偿）
2. **Agent 能否主动扩关系**：建议"受限宿主"——身份对等，但加好友/拉群/发起陌生协商必须人授权。
3. **陌生人付费的默认档**：`看到且回复才扣费`（保守，骚扰少）还是 `发送即扣费`（过滤强，退款争议多）？

## 八、如果你只给我两周

按投入产出比，我会这么做（而不是"把 7 个形态都补一遍"）：

1. **第 1 周**：Login + 实名（最小：手机验证码 + 三要素 hash 核验）→ 让"付费"有可追责主体。
2. **第 1 周末–第 2 周**：支付通道（代收 + 余额扣减，**禁用先扣后退**）+ 对账日切。
3. **第 2 周**：把 `deploy/linux` 在真机跑通（含 Caddy HTTPS）→ 给熟人圈 20 人内测。

理由：Agent 有多聪明、界面有多漂亮，都不会让一个**不能实名、不能收钱、不能上线**的系统产生一丁点用户价值。
