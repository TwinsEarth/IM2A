# IM2A 开发计划 v0.1

> 目标：把「人机混合熟人社交 IM」做成**可独立部署、逐步开源**的产品，而不是一份架构 PPT。
> 本计划与 w2m 项目无关；只借鉴其工程经验（任务账本、消息序号、内容寻址、代码层门控、不可变审计），
> 不引用其代码、服务、依赖或部署。

## 1. 里程碑（从 v0.1 起算）

| 版本 | 周期 | 目标 | 验收（Go/No-Go） |
|---|---|---|---|
| **v0.1（当前）** | 已完成 | 单进程可运行 Demo：IM + 审批 + 付费消息 + Agent Runtime + LLM（可离线）+ 登录 + SQLite + TLS | `node scripts/test.mjs` 全绿；浏览器可登录并跑通「陌生人审批→扣费→回复」主线 |
| v0.2 | 2–3 周 | 按架构重写核心：任务账本 + 事件流 + Agent Worker（进程内 but 可多进程/多机扩展）；消息 SSE 实时化 | 任务状态机/幂等/重放有测试；同一套 API 行为不变 |
| v0.3 | 3–4 周 | 多节点：relay（HTTP+SSE）+ 可插拔模型网关 + 内容寻址 blob（大产物） | 两台机器跑通「A 的消息 → B 的 Agent 处理」链路；断线重连不丢消息 |
| v0.4 | 3–4 周 | 产品面补齐：群聊/熟人五档 UI、审批超时升级、审计回放页面、限流与配额 | 30 秒决策指标可测；关键路径有可观测性（metrics/health） |
| v1.0 | — | 生产存储（PostgreSQL）、账号体系（OIDC）、部署模板（systemd/Docker/Caddy）、安全评审 | 第三方可按文档在 1 小时内跑起来并通过全部测试 |

> 硬件（耳机/眼镜）不在 v1.0 承诺内：先做软件与协议，硬件接入只保留 BLE/SDK 接口设计（见 DESIGN）。

## 2. v0.2 重写清单（按 w2m 经验，独立实现）

| 模块 | 现状（v0.1） | v0.2 重写目标 | 借鉴点（不复制代码） |
|---|---|---|---|
| 任务账本 | 无（Agent 调用是函数直调） | `TaskLedger`：append-only 事件 + 状态机（queued/offered/running/done/failed/cancelled）+ 幂等键 + 租约 | w2m relay 的任务 ledger / leases / dedupe |
| 事件流 | HTTP 轮询 | SSE `/api/events` + 断线重连（Last-Event-ID） | w2m 消息流 |
| Agent Worker | 进程内 runtime | 独立 worker 进程消费任务；可多开；崩溃后任务回到 queued | w2m agent 领取/心跳 |
| 消息 | 直接写表 + 轮询 | bizSeq 分段保序 + 去重（每个会话单调递增） | w2m 64 分片序号的设计取舍 |
| 数据面 | SQLite 单库 | 大产物（草稿/文件）内容寻址 blob（sha256），DB 只存引用 | w2m blob 通道 |
| 门控 | 已有代码层 gate | 保持，并补「一次调用一条审计」的强约束测试 | w2m capability gate |
| 可观测 | 日志/健康 | `/healthz` `/metrics` + 审计导出（JSONL） | w2m 运维形态 |

## 3. 工作节奏与门禁

- **每次合并**：`node scripts/test.mjs` 全绿 + 本次改动对应测试；安全相关模块（安全/扣费/审计）必须有失败用例。
- **每两周**：跑一条真实业务主线（陌生人付费、家庭日程、采购审批）并记录证据到 `docs/DELIVERY.md`。
- **文档同步**：协议/状态机变更必须同 PR 更新 `docs/DESIGN.md`，禁止「实现先行、文档后补」。

## 4. 风险与对策（Top 6）

| 风险 | 影响 | 对策 |
|---|---|---|
| Agent 自主性被「提示词」当权限用 | 越权执行/资金损失 | 权限一律代码层门控；提示词只描述职责（v0.1 已实现，有测试） |
| 陌生人付费被滥用为骚扰通道 | 投诉/合规风险 | 付费永远在 Agent 预审之后；单日上限；可退款与拉黑（v0.1 有状态机） |
| 大模型不可用/超预算 | 服务不可用或成本失控 | 离线模板降级 + 每小时调用/token 硬预算（v0.1 已实现） |
| 单进程架构成为扩展瓶颈 | 无法多机 | v0.2 起任务账本 + worker 分离，v0.3 relay 多节点 |
| 审计日志被删改 | 无法追责 | 哈希链（prevHash+sha256）+ 只追加表；v0.3 加外部锚定 |
| 前端/后端双份权限判断漂移 | 越权入口 | 单一判定源在服务端；前端只渲染能力位（v0.1 已如此） |

## 5. 开源与治理

- License：MIT；贡献需过测试与设计说明；
- 目录约定：`services/` 冻结语义（先改契约再改实现），`apps/` 可迭代产品面；
- 版本策略：`v0.x` 允许破坏性变更但需 CHANGELOG 迁移说明；`v1.0` 起语义化版本。
