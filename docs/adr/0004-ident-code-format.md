# ADR 0004: Identity-code compatibility format and credential separation

## Status

Accepted for the `ident-code 1.0` compatibility layer (2026-10-30).

## Context

The product requested a 128-character "unique identification code" made of
35 clear characters and a 93-character suffix described as a private key. That
shape is useful as a compact public address plus an opaque credential prefix,
but it is cryptographically unsafe to place a real private key inside a value
that is copied, screenshotted, logged, pasted into chat, or stored by clients.

## Decision

1. Keep the requested outer lengths:
   - user code: 25 chars (`IM2A_YYYYMMDD` + 12 digits)
   - public UID: 35 chars (`IM2A_YYYYMMDD` + 12-digit user + 10-digit Agent)
   - auth code: 128 chars (35-char public UID + 93-char opaque secret)
   - IM2A number: 12 digits (11 payload + Luhn check digit)
   - Agent subcode: 10 digits, scoped to the owner
2. The 93-character suffix is **not a private key**. It is generated by a
   CSPRNG and stored server-side only as an HMAC fingerprint. Signing keys and
   peppers stay in KMS/secret storage.
3. Public codes never authorize. They resolve to a minimal public projection
   only. The auth code is a separate credential-plane object, accepted only by
   the credential verifier, never by public lookup.
4. Auth codes are short-lived (5–30 min), single-use, audience-bound, and
   scope-bound. Verification is constant-time and atomic.
5. Agent subcodes are owner-scoped and reusable only under the owner after the
   policy quarantine; they do not create a second global identity namespace.
6. All endpoints (server, Harness plugins, browser extension, WeChat Bot) must
   use the shared codec/schema and may not invent a parallel parser or accept a
   public code as a bearer credential.

## Consequences

- Existing gateway bearer-token authentication remains a separate mechanism
  until the principal/tenant model and credential service are implemented.
- A code that contains a real private key is rejected by review and by the
  validator; it must be rotated/revoked if ever issued.
- The codec and schema are the cross-end contract; production storage and
  resolution follow `docs/design/IM2A-CODE-SERVICE-ARCHITECTURE.md`.
