### 3.3 设计要点（本版唯一的新语义）

1. **三层接口映射（禁止第四套命名）**：对外只暴露 `WORKING/EPISODIC/SEMANTIC`；内部映射 §33 `PERSONAL→SEMANTIC`（长期画像/边界）、`TASK→EPISODIC`（任务检查点）、`WORKING→WORKING`（单次执行，永不进迁移包）。映射表进 §53。
2. **写入权**：任何 Agent（含 butler）只能 `propose`；`confirm` 仅属主；`LOCKED` 值不可覆写，冲突上抛 `CONFLICT`，不自动合并（与 §34 不变量一致）。
3. **隔离**：子 Agent 读不到兄弟 Agent 原始记忆；butler 只拿 digest（计数/摘要，不含 content）；与 §6 `MEMORY_ISOLATED` 同一判定。
4. **Improvement Memory 只收紧**：反馈只能建议——提高 `approvalThresholdCents`/收紧 `maxAmountCents`、提高 `trustZoneMin`、把 skill 加入 `destructiveSkills`；放宽必须人工批准并留审计；改进记录是 advisory，不自动改策略。
5. **Model Provider 三条硬约束**：①模型只起草，不执行（im2agent 铁律）；②敏感域/家庭信任档 → 本地或拒绝上云（复用 §24，不改判定）；③降级必须显式 `degraded` + 指标，**禁止把模板输出伪装成模型输出**。
6. **成本口径**：每次调用记录 `provider/model/tokens/estimatedCostCents`（估算，⚠ 单价需采购/财务复核）；无 key 只走 template，成本 0。

### 4.2 目标（一条流 + 一条链）

| 目标 | 落点 | 提案 |
|---|---|---|
| 协商双向流：WS 双向、8 态实时推送、事件 id 去重、断线按 `seq` 补拉、**终止只推一张审批卡片** | `services/messaging/src/negotiation-stream.mjs` | 扩展 §5/§48（R26） |
| 付费链路：**预审 → 定价 → 发送即扣 / 回复才扣 → 查看 → 退款**，§9 为唯一状态机 | `paid-message` 接线 + `pricing` 规则 | 扩展 §9/§35/§49（R26） |

### 4.3 设计要点

1. **WS 传输**：零依赖下用 `node:http` 的 `upgrade` 实现最小 RFC6455 服务端（帧/掩码/ping-pong/close），测试用 Node 内置 `WebSocket` 客户端（本机 Node 24 可用；Node 22 的支持程度 ⚠ 需按目标机复核）；事件格式复用 §48（`topic+payload+id+origin`），每事件每连接最多投递一次。
2. **8 态推送**：`SUBMITTED/WORKING/INPUT_REQUIRED/AUTH_REQUIRED/COMPLETED/FAILED/CANCELED/REJECTED` 每次迁移发一条带 `sessionId+turnSeq+state+eventId` 的事件；客户端按 `eventId` 去重、`turnSeq` 排序，断线重连带 `lastSeq` 补拉。
3. **终止语义**：只有终态（含两个“需人介入”中断点）产出用户可见物；`COMPLETED` 只推**一张** `ApprovalTicket`（`ticketType=NEGOTIATION|PAYMENT`），中间轮次不可见（§5 不变量不放松）。
4. **定价只记录、不扩权**：纯函数 `(billingMode, amountCents, trustLevel, dailySpentCents) → quote`，输出金额+依据；`priceCents` 不参与授权判定（§35 铁律）；上限由日上限与审批阈值兜底；**禁止模型定价**。
5. **两种计费 + 统一状态机**：`SEND_PAY` 发送时扣、`VIEW_REPLY_PAY` 查看/回复时扣；同一 `messageId` 重复 `pay()` 返回 `charged:false`；退款仅 `PAID/VIEWED`，`REPLIED` 后走 §39 争议；M2 起产品 app 必须走 §9，删除 `domain.mjs` 内联状态或降级为视图投影。

### 4.4 迁移路径（可回退）

1. 冻结 R26（扩展 §5/§9/§14/§35/§48/§49，只加不改）。
2. 落 `negotiation-stream` + 单测，接 §5/§14/§48/§25；灰度：WS 开 / 轮询回退（保留一个版本）。
3. 付费接线：§40 `canDeliver` → 定价 quote → §9 状态机 → §37 扣费/§35 回执 → §49 渠道/§50 对账；灰度：旧内联/新 §9 双模式 + 差异对账。
4. 全量切 §9，旧路径只读一版后删除；回退 = 关开关回旧路径（账本只追加，无需回滚）。

### 5.4 腾讯云 IM 适配（基于 §31 扩展）

1. **UserSig**：服务端签发短期凭证，客户端不持长期密钥；⚠ 签名算法/有效期按官方文档复核（不编参数）。
2. **Webhook**：验签 → `normalizeEvent` → §14/§15；重复投递按 `platformMessageId` 幂等；失败进重试队列，不静默丢弃。
3. **补拉与未读**：登录后按 `lastSeq` 补拉；`AGENT_NEGOTIATION` 未读恒 0 若 PaaS 不具备（缺 `UNREAD_SHAPING`），**必须显式拒绝该用法**——协商流因此留在自建 WS，不上 PaaS。
4. **三流量隔离**：人类 IM→PaaS；协商→自建 WS；审批/审计→Kafka+审计存储；三者在消息 ID/审计 ID/限流配额上独立，验证脚本检查“协商事件不产生人类未读”。
5. **能力声明**：`createTencentImPaasAdapter` 现只声明 `AUDIT_CHAIN`/`CARD_CALLBACK`；M3 补齐可支持项，**不支持项保持缺失让调用方显式失败**（§31 不变量）。

### 5.5 迁移顺序（强串行）

`契约冻结 R27 → §56 存储 PG 稳定（含双写/回滚演练）→ §57 Kafka（与 §56 可并行，但必须在同一迁移窗口内完成 outbox 持久化）→ §58 IM 通道切换（独立联调、**最后切换**）→ 三流量隔离验证`。与 [38 §4.2](./38-模块与接口契约规划.md) 一致：§56/§57 可并行，§58 独立；但通道切换不可与其他变更同窗口，否则无法定位故障。

## 8. 横切设计

### 8.1 身份与授权

| 项 | 现状 | 演进 |
|---|---|---|
| Agent 身份 | §11 自签卡片 + §26 签名信封（TOFU） | 服务间请求统一过 §12 网关；不新增“内部网络即可信” |
| 授权 | §35 scope+单次回执；§30 委托衰减 | M2 接付费查看/回复；M4 增加设备 scope；**付费不扩权**（`priceCents` 只记录） |
| 人机边界 | §4 九态、§32 来意挂起、§28 确认层不可被 planner 预批准 | 对外动作（发消息/扣费/改单）必须落确认层；模型只起草 |
| 设备身份 | ⛔ | M4 独立设备密钥，可单独吊销，不与用户密钥混用 |

### 8.2 审计与可观测

| 层 | 现状 | 演进 |
|---|---|---|
| 审计 | §16 哈希链+签名审计，只追加 | M3 起审批/账本/门控经 outbox→Kafka→审计存储；DB 是取证副本 |

### 8.3 容量与性能预算（全部规划值，⚠ 需实测回填）

| 指标 | 目标 | 验证方式 |
|---|---|---|
| 审批卡片推送 P99 | ≤ 2s（前台；后台只承诺到达） | 端到端埋点 + accept Gate ⚠ |

| 存储增长 | 账本/审批/审计按条线性增长 | 迁移演练抽样 ⚠ |

### 8.4 降级策略（继续收费的前提是账本可写）

| 故障 | 降级 | 是否允许继续收费 |
|---|---|---|
| IM PaaS 不可用 | 人类通道待重连补拉；卡片转站内待办；协商 WS 不受影响 | ✅ 可（付费写入不经 PaaS） |
| WS 不可用 | SSE → 轮询；协商暂停或降频 | ✅ 可（状态机幂等） |
| 模型不可用 | template 兜底并标 `degraded`；敏感域拒绝上云 | ✅ 可（模型不参与授权） |
| 支付渠道不可用 | 停新充值；已扣费消息走完 | ⚠ 仅存量 |
| **PG/账本不可写** | **拒绝新付费、审批只读**；不降级写 jsonfile | ❌ 不可（宁停不双写） |
| Kafka 不可用 | outbox 积压、审计延迟；业务继续 | ✅ 可（有 outbox + 告警） |

### 8.5 兼容性（§1–§52 只加不改）

| 维度 | 规则 |
|---|---|
| 契约 | 新能力进 §53+（加法）；改既有语义须 R# 标注并视为不兼容，不得静默漂移 |
| API | 新增字段可选、旧字段不删；破坏性变更走新前缀（M3 评估 `/api/v1`，旧路径保留） |
| schema | 路线：2（基线）→ **3**（M1 Context 四表）→ **4**（M3 物理 PG）→ **5**（M5 主权表）；升级必须 `schemaVersion+1` + `migrate-state.mjs` + dry-run；不匹配显式 `SCHEMA_MISMATCH`，不猜测迁移 |
| 客户端 | 最低版本矩阵由 `compatibility-policy`(§62) 冻结；功能降级由服务端开关控制 |

## 10. 风险与不做什么

### 10.1 风险登记（技术类；产品/资源风险见 [39 §7](./39-版本计划与资源门槛.md)）

| # | 风险 | 触发信号 | 缓解 |
|---|---|---|---|
| T1 | **双写分叉**（最容易被低估） | 两侧账本条数/哈希不一致；回滚后差异无法归因 | 迁移期只允许一个可写主；账本唯一索引；差异清单 + 冲正（不删） |
| T2 | Context 两套分层命名漂移 | 出现第四层命名/两套 stage | §53 只认 `WORKING/EPISODIC/SEMANTIC` + 映射表；评审一票否决 |
| T3 | 协商实时化丢包/重复 | 事件重复率 >0、状态回退、乱序终态 | 先状态机幂等再推送；`eventId` 去重 + `seq` 补拉；保留轮询开关 |
| T4 | IM 适配器“假装支持”未读整形 | 协商事件产生人类未读 | §31 能力缺失即 `CAPABILITY_MISSING`；协商不上 PaaS |
| T5 | 模型降级伪装成功 | `degraded` 未标记、模板话术当模型输出 | 降级显式标记 + 指标 + UI 提示 |
| T6 | 付费两套真相 | 产品 app 与 §9 状态不一致 | M2 强制 §9 唯一状态机；旧路径只读一版后删除 |
| T7 | Flutter 未编译导致 M4 虚报 | 无 `flutter analyze` CI、无真机 | 未编译不得写“已支持”；M4 出口以 CI+真机为准 |
| T8 | 数据主权承诺无证据 | 拿不出抓包/断网/审计证据 | 证据三件套先定义再开工；无证据的承诺删除 |

### 10.2 明确不做（防路线膨胀）

| 不做 | 原因 | 何时重评 |
|---|---|---|
| Temporal/工作流引擎、K8s、服务网格、自研共识 | 内测/单节点用不到；运维成本 > 收益（[36 D4](./36-演进路线与版本总规划.md)） | 跨系统长事务/多地域时 |
| 微服务按 §1–§52 拆几十个服务 | 当前 12 目录足够；拆分会放大分布式问题 | 单库/单进程触顶后 |
| 自研 IM 长连接内核 | Phase0–1 用 PaaS + §31 适配层 | 成本/合规不满足时 |
| Milvus/独立向量库 | M3 先用 pgvector；阈值触发再迁（[02 §9](./02-技术选型与框架.md)） | 行数/QPS/P99 触阈值 |
| 端侧 LLM / 全量离线 Agent | 端侧只做守门；算力/功耗未验证 | M4 样机实测后 |
| 多租户/分账/发票/chargeback | 商业阶段能力；当前无真实资金 | 商业版本 |
| A2A 跨组织开放、LLM 定价/LLM 当审批人 | 授权真空未解；违反三条不可妥协原则 | Phase3 且法务同意 / 永不 |
| 硬件量产（M4 只做 BLE 桥接与样机验证） | 供应链/认证未就绪 | 硬件立项后 |

### 10.3 一句话风险（评审必看）

**最容易被低估的不是向量检索或 WS 性能，而是 M3 双写窗口的“账本分叉”：账本只追加、跨存储没有全局唯一索引，一旦双写与回滚路径没设计好，两边各记一份且无法用重放修复——这比“迁移慢”严重一个数量级。**
