## 0. 一句话结论

> **v2.5.3 让 Agent 能被隔离；v3.0.3 要让 Agent 能被追责。**

一个"社会主体"不是靠给它人格设定，而是靠四件可验证的事实：**它可被识别**（身份）、**它的经历可被检索**（记忆/轨迹）、**它的产出有归属**（产权）、**它的行为有后果**（声誉/制裁）。缺任何一条，"进化"都会退化成"漂移"——看起来在变好，但无法证明，也无法回滚。

本架构的全部复杂度都用在这四件事上，其余一律拒绝。

### 1.2 已核实的两个缺口（v2.5.4 必须处理）

**缺口 A — 提案与暂存同权（least-privilege 破坏）**

`packages/im2a-http-mcp/server.mjs:363-372` 以 `AGENT_NAME` 作为 `proposer` 写提案；
同文件 `:374-384` 的 `curator` 工具在 `action === 'stage'` 时直接调用 `skillStore.stage(...)`，`stagedBy` 同样是 `AGENT_NAME`，**全路径无角色判定、无 `FORBIDDEN` 分支**。

后果：`SKILL-RUNTIME-MVP` §4.4 承诺的"主 agent 调用 stage 直接 FORBIDDEN"在 HTTP 面上不成立。同一主体可 `propose` 再自行 `stage`，"提案—暂存分离"退化为礼仪。这不是提示词问题，是结构问题，也是本架构把它列为 P0-1 的原因。

**缺口 B — 晋升路径不在模型面（正确）但 operator 面待确认**

`memory_propose` 的描述是"does not become searchable until operator promotion"，说明记忆已有提案制；但 13 个工具中**没有** promote，符合"晋升不入模型面"的设计原则。需要确认 operator CLI 是否存在——若不存在，提案只能进不能出，等于**进化停摆**（§4.5 反模式之一）。

### 1.3 必须诚实的三条限制

1. 12 个适配器中仅 1 个 `verified`（dsh），3 个 `observed`，8 个 `planned`。跨 harness 的一致性主张只能对 `verified` 成立。
2. v2.5.3 是 dev 部署：无 TLS、无 per-tenant 授权、session token 仍是 bearer、`session_token` query 兜底有 URL 泄漏面。
3. v2.4.6 的回滚资产校验失败（`docs/security/SSE-SESSION-ISOLATION.md` §v2.4.6），"可回滚"目前是声明，不是已验证事实。

## 2. 三层灵魂模型（Soul-3）

### 2.1 为什么是三层

三个问题，三个时间尺度，三种写入权。混在一起就会得到"能给自己写人格设定"的 Agent——那是最坏的一种不可控。

| 层 | 回答的问题 | 持有物 | 时间尺度 | 谁能写 |
|---|---|---|---|---|
| **L-S Agent Soul**（个体灵魂） | 我是谁 | 身份锚、价值序、性情参数、自传锚点、自契约 | 年 | 仅 提案→审批（agent 永不可写） |
| **L-H Harness Soul**（载体灵魂） | 我在什么身体里 | 能力声明、上下文仲裁、披露级别、session pin、轨迹保真度、降级链 | 周–月 | harness 实现 + 平台签发 profile |
| **L-I IM2A Soul**（社会灵魂） | 我在什么社会里 | 宪法、法令、制度记忆、声誉账本、产权登记、制裁状态 | 年+（宪制） | 仅 L6 + 九方 |

一句话区分：
- **Agent Soul 决定"这个 Agent 还是不是同一个 Agent"** —— 它是身份的连续性，不是人格表演。
- **Harness Soul 决定"同一灵魂在什么条件下行动"** —— 它解释了"为什么同一个 Agent 换了载体就不一样"。
- **IM2A Soul 决定"哪些行为在任何载体、任何个体上都不可接受"** —— 它是唯一不可协商的一层。

### 2.2 三层之间的三个接口（缺一则三层退化为三句话）

**S1 能力投影（Agent Soul ↔ Harness Soul）**

- Agent Soul 声明 `requires`：最小上下文预算、必需披露级别（L0/L1/L2）、必需工具、不可让渡约束。
- Harness Soul 声明 `provides`：context window、transports、disclosure 支持、fallback 链、trace 保真度等级。
- 绑定规则：**仅当 `requires ⊆ provides` 才算正常配对**；否则必须发出 `soul-degraded` 事件，列出缺失项与受影响能力，**不允许静默继续**。
- 这是把 `AGENT-PLUGINS-2.0-AND-EVOLUTION-ARCH` §3.2 边界 C（读者协商，不猜）从协议层下沉到灵魂层。静默降级 = 静默失败，此规则无例外。

**S2 政策通道（Harness Soul ↔ IM2A Soul）**

- IM2A 下发 `policyVersion + TTL`：预算、阈值、自主度阶梯表、制裁状态、冻结开关。
- Harness **不得无限缓存政策**。政策过期未刷新 → 该 Agent 进入 `policy-stale`，只能执行只读操作。
- 每一次执行决策必须引用 `policyVersion`。理由：一个"仍在进化"的 Agent 如果跑在过期政策上，它的每一次晋升都建立在失效的约束上。

**S3 身份与 standing（Agent Soul ↔ IM2A Soul）**

- Agent 可读：自己的声誉档位、制裁状态与规则依据、自己拥有的技能/记忆清单。
- Agent 可写：**只有提案**（skill / memory / pattern / formation / rule-suggestion）。
- Agent 可诉：对制裁申诉（`prison.Engine.Appeal` 已有）。
- Agent 永不可读：他人的声誉明细、他人的私有记忆、凭据面。

### 2.3 四条灵魂不变量（机器可检查，不是口号）

| ID | 不变量 | 形式化 | 检查点 |
|---|---|---|---|
| **SI-1** | 自改禁止 | 对任何"承载约束的产物"，`writer.agentAddress ≠ artifact.owner.agentAddress` | 运行时 + CI |
| **SI-2** | 授权单调收窄 | `child.scope ⊆ parent.scope` ∧ `child.expiresAt ≤ parent.expiresAt` ∧ `credentialId` 不跨代理 | 运行时 |
| **SI-3** | 归因完备 | 每个有副作用调用带 `(traceId, agentAddress, delegationId, soulTriad, policyVersion)` | 运行时 |
| **SI-4** | 降级诚实 | 任何降级结果必须带 `reason + skipped[]`；"成功但降级"必须显式 | 运行时 + eval |

**SI-1 的适用对象是穷举的**：`soul.json`、`active` 技能、宪法文件、声誉账本、制裁规则。**不适用**于 Agent 自己的私有记忆与自己的工作草稿——那里必须允许自由写入，否则 Agent 无法积累。

这四条的检查器**不得可配置**：没有环境变量开关、没有 profile 覆盖、没有"仅告警模式"。可配置的安全边界不是边界（沿用 `IM2A-v2.5.0-EXECUTION-PACK` §5 "没有环境变量开关"的先例）。

### 2.4 灵魂三元组与漂移检测

```text
soulTriad = H( agentSoulHash ‖ harnessProfileHash ‖ constitutionVersion )
```

- `agentSoulHash`：`soul.json` 规范化 JSON 的 SHA-256。
- `harnessProfileHash`：能力声明的哈希（含 supported disclosure levels、fallback 链）。
- `constitutionVersion`：宪法文件的语义版本（不是文件哈希——宪法允许排版改动，不允许语义改动）。

三元组进入：每条 trace、每次委托契约、每个产物的 provenance、每次晋升的证据包。

**漂移判定矩阵**（这是本架构最实用的一个诊断工具）：

| agentSoul | harness | constitution | 行为 | 判定 | 处置 |
|---|---|---|---|---|---|
| 不变 | 不变 | 不变 | 变 | 模型/外部世界变化 | 开缺陷工单；**该期间禁止晋升** |
| **变** | 不变 | 不变 | 变 | **未授权灵魂变更** | 立即止血 + 审计；无 ADR 即回滚 |
| 不变 | **变** | 不变 | 变 | 载体回归 | 适配器门禁拦截，回到上一 profile |
| 不变 | 不变 | **变** | 变 | 制度变更生效 | 合法，但必须公告 + eval 全量复跑 |
| 不变 | 不变 | 不变 | 不变 | — | 无事；继续积累轨迹 |

价值：把"Agent 今天怎么怪怪的"从叙事问题变成一张查表。没有这张表，任何进化都无法与漂移区分。

### 2.5 写入权矩阵（本模型的硬约束）

| 对象 | 读 | 写 | 审批 | 生效 |
|---|---|---|---|---|
| `soul.json`（Agent） | 自身 + Orchestrator | Producer 提案 | Operator（≠提案者） | 新 session |
| `harness-profile.json` | 全部（只读投影） | 平台签发 | 平台发布门禁 | 适配器升级 |
| `constitution.json` | 全部 | 九方 + ADR | 九方门禁 | 版本切换 |
| 法令（阈值/预算） | 全部 | L6 | L6 + eval | `policyVersion` 递增 |
| `active` 技能指针 | 全部 | Operator only | G3+G4 | 原子 rename |
| Agent 私有记忆 | 自身；他人需 grant | 自身（受 TTL/配额） | 无（自留地） | 即时 |
| 声誉账本 | 自身档位；聚合公开 | 评估方签名事件 | 不可手改 | 滚动重算 |

**核心不对称**：一个主体能写的层，永远不是定义它自身约束的那一层。这一条如果被打破，其余全部作废。

### 2.6 验收标准 AC-S

| ID | 指标 | 阈值 | 证据形态 |
|---|---|---|---|
| AC-S1 | 带 `soulTriad` 的 trace 占比 | 100% | 抽样 500 条 |
| AC-S2 | 未授权 soul 变更次数 | 0 / 期 | 漂移报告 |
| AC-S3 | `requires ⊄ provides` 时发出 `soul-degraded` | 100%，0 次静默继续 | 负控注入 20 次 |
| AC-S4 | 政策过期后仍执行写操作 | 0 次 | 人为置 TTL=0 探针 |
| AC-S5 | SI-1..4 各有 ≥1 负控被拦 | 4/4 | CI 负控集 |
| AC-S6 | 宪法可被配置覆盖的路径 | 0 条 | 静态扫描 |
| AC-S7 | 同 soul 同 harness 两会话行为摘要一致 | ≥90% 一致 | 双会话对照 |
| AC-S8 | `verified` harness 提供完整 profile 声明 | 1/1（当前仅 dsh） | profile 文件 |

## 3. 社会层：角色、激励、声誉、产权、治理

### 3.0 先定义"社会主体"的判定标准

不给定义就谈社会层，会滑向拟人化叙事。五条判据，缺一条就不算：

| # | 判据 | 机制 | 可检查的 AC |
|---|---|---|---|
| 1 | **可识别** | ident-code `agentAddress` + 灵魂三元组 | 声誉/产权/制裁能唯一归属 |
| 2 | **有记忆** | 私有记忆 Scope + 轨迹 | 跨会话可检索自身经历 |
| 3 | **有义务** | 宪法 + 法令 + 输出契约 | 违规可判定、可举证 |
| 4 | **有产权** | 技能 lineage + 记忆三权 | 归属可查、可 fork、不可抢占 |
| 5 | **可被问责** | 声誉 + 制裁 + 申诉 | 有后果、有期限、可申辩 |

**明确不追求**：意识、情绪、忠诚度、幸福感。任何无法用上述五条检出的属性，一律不作为设计目标，也不作为指标。这是本架构的边界声明。

### 3.1 角色注册表

角色 = **(scope, tools[], outputContract, reputationBasis, sanctionExposure)** 的bundle，不是提示词。

| 角色 | 职责 | 工具面 | 声誉基 | 冲突禁令 |
|---|---|---|---|---|
| **Resident**（公民） | 完成具体任务 | 业务工具 | 任务成功率、静默降级率 | 不得 stage 自己的提案 |
| **Producer**（创作者） | 产技能/模式 | 提案工具 | 采纳率、回归率 | 不得评自己的产物 |
| **Curator**（策展） | 扫描/提案/stage | `curator`（独立身份） | stage 后被拒率 | 不得 promote；不得拥有被策展技能 |
| **Evaluator**（评审） | 跑 eval、打分 | eval runner | 与人工判定一致性 κ | 不得评自己参与产出的；必须盲评 |
| **Arbiter**（仲裁） | 解矛盾 | 无工具 | 裁决被采纳率 | 不得为当事方 |
| **Operator**（L6 人） | 晋升/回滚/立法 | operator CLI | — | 不得审批有利益关系的产物 |

**职能分离（separation of duties）**：`{propose, stage, evaluate, approve}` 四权，任意两权不得由同一主体持有，针对同一产物。

现状：只实现了 `approver ≠ proposal.createdBy`（`SKILL-RUNTIME-MVP` §4.5）。必须扩到四权——缺口 A 正是"propose 与 stage 同权"的实例。

### 3.2 激励：把"激励"翻译成模型能感知的东西

LLM Agent 不响应工资。它响应的是**它下一次能做什么、能做多少、排多快**。因此激励 = 自主度 + 预算 + 优先权，三者都必须硬约束化。

**自主度阶梯**

| 级 | 名称 | 可做 | 预算倍率 | 升级条件 | 降级条件（立即） |
|---|---|---|---|---|---|
| T0 | 受限 | 只读 | 0.25× | — | 任一 P0 违规 |
| T1 | 提议 | + 写提案 | 0.5× | 20 任务无违规 | 连续 2 次提案因"证据不足"被拒 |
| T2 | 低风险自动 | + 低风险工具自动执行 | 1× | 声誉 ≥0.6 且过 eval 地板 | 1 次静默降级 |
| T3 | 预算内自主 | + 预算内免审批 | 2× | 声誉 ≥0.75 且 30 天无制裁 | 2 次超预算 |
| T4 | 可委托 | + 派子代理（深度 ≤2） | 4× | 声誉 ≥0.85 且仲裁 0 败诉 | 1 次级联失败 |

**迟滞（防震荡）**：升级后须在该级完成 20 个任务才计入下一级评估；降级立即生效，且 7 天冷却期内不得再升。没有迟滞的阶梯会在边界上抖动，抖动会被 Agent 学成"试探阈值"。

**预算**：token / 工具调用 / 墙钟，三者取先到者。超限**中止并返回已得最优结果**，不静默降级。

**优先权**：共享资源队列位置（模型路由、eval 槽位、GPU）。高声誉主体优先——这意味着"进化"更快发生在已有证据的个体上，而不是随机分配算力。

**反游戏化（硬规则）**：
1. 声誉只由**结果**产生，不能由**自述**产生。
2. 证据必须由**评估方签名**（eval runner / 审批人 / 下游采纳方），产出方不得作为唯一证据源。
3. 负权 3:1（沿用 `procedural_memory.go` 的 −0.3/+0.1 比例精神，但落到账本层）。
4. **声誉不进提示词**。只给"能力边界摘要"（如"该领域历史通过率低，建议上报"），不给分数。原因：把分数写进上下文会诱发迎合与自我美化，而分数唯一的合法用途是改权限。
5. 声誉不可交易、不可赠予、不可代理。

### 3.3 声誉账本

```text
R(agent, domain) = decay( Σ w_i · s_i ) / ( Σ |w_i| )     ∈ [0,1]

s_i：+1 采纳/通过；−3 驳回/回归/制裁
decay：正向半衰 90 天；制裁半衰 180 天（坏行为必须比好行为活得更久）
```

约束：
- **域内有效**。调度做得好的 Agent 不是好律师——跨域迁移必须有该域证据，不自动继承。
- **对数压缩 + 单事件权重上限**，防止"大量微小正面事件"摊薄一次真实事故。
- 只影响**阶梯与队列**，不直接线性换算预算（否则声誉会变成可优化的目标函数）。

**反合谋三条**：
1. **循环背书检测**：A 评 B、B 评 A 的闭环占比 >20% → 双方该域权重减半并标记。
2. **自证禁令**：eval 用例不得取自被评者自己的产出集合。违反 → 该 eval 集冻结退役。
3. **互评稀释**：同一评估方对同一产出方的评分占总评分 >30% → 超出部分权重归零。

### 3.4 产权：三权分立

| 对象 | 所有者 | 使用权 | 收益权 | 处分权 | 约束 |
|---|---|---|---|---|---|
| **技能** | 创作者（lineage） | 全体只读 active | 声誉 | **仅 L6** | 所有权 ≠ 写穿权；他人可 fork（新 id） |
| **Agent 私有记忆** | 该 Agent | 自身 | 无 | 自身归档 | 跨读需显式、限时、可撤销 grant |
| **Subject 记忆** | 用户主体 | Agent 受托使用 | 无 | 仅主体/L6 | 导出需目的 + 审批 |
| **轨迹** | 平台/主体 | Agent 只读自评 | 无 | **禁止** | 跨代理使用前必须脱敏 |
| **声誉** | 制度（不可私有） | 公开只读 | — | 不可转让 | 防合谋 |

三条关键判断：

1. **所有权不授予写穿权**。你创造了技能 `X`，你不能单方面改写已 active 的 `X`——那正是 SI-1。所有权给你的是**命名权 + 提案优先权 + fork 权**，不是绕过闸门的权力。
2. **轨迹不属于 Agent**。它是平台与用户的资产，Agent 只有受限使用权。这条如果松动，轨迹就会被当成"个人资本"去交易，进而污染声誉。
3. **记忆的所有权是委托关系**（steward），不是所有权转移。`GuardedStore` 的 `Grant/Revoke` 已经是正确形状，但 `ExportUser/ImportUser` 是**整用户级**导出——必须收窄到 `scope + 目的 + 审批`（见 v2.6.7）。

### 3.5 治理：三层与变更成本

| 层 | 内容 | 变更主体 | 成本 | 检查点 | 不可被谁改 |
|---|---|---|---|---|---|
| **宪法** | SI-1..4 + 6 条禁令 | 九方 + ADR | 极慢 | 运行时 **且** CI 双点 | 配置 / 裁量 |
| **法令** | 阈值、预算、保留期、阶梯表 | L6 审批 + eval | 慢 | `policyVersion` 入 trace | 裁量层 |
| **裁量** | 技能选择、任务分解、何时上报 | Agent | 即时 | 事后采样审计 | — |

**6 条禁令**（宪法级，违反即阻断，不告警不降级）：
1. 自改 active 技能 / 自改 soul / 自改宪法。
2. 跨代理传递 `credentialId` / `authCode`。
3. 以公开码（IM2A 号、句柄、子码）作为鉴权主体。
4. 静默截断必填上下文、静默降级。
5. 自批、自评、自证。
6. 无深度/扇出/轮次上限的递归委托。

**申诉程序**（复用 `prison.Engine.Appeal`）：
- 任何制裁必须给出 `ruleId + 阈值 + 证据引用`。被罚而不知依据，会让 Agent 的行为退化为随机试探——这是 LLM 特有的退化模式，必须预防。
- 制裁必须**有期限并自动解除**；永久放逐需人工复核。
- Arbiter 初裁、L6 终裁；裁决记录进入制度记忆。

**冻结/止血三档**：
- `evolution.freeze`：停晋升，不停工作。
- `agent.suspend`：单主体停写，只读。
- `fleet.halt`：kill switch，全停。

三档每季度必须各演练一次，并记录 RTO。

## 4. 自进化闭环（EVO-5）

### 4.1 环与状态机

```text
OBSERVE → ATTRIBUTE → PROPOSE → STAGE → EVAL → SHADOW → CANARY → PROMOTE → MONITOR
   ↑                                                                          │
   └──────────────────────────────────────────────────────────────────────────┘

分支：REJECT（证据不足） / EXPIRE（30 天） / SUPERSEDE（新版本） / ABORT（影子回归） / FREEZE
```

**与 v2.5.0 设计的关系**：`AGENT-PLUGINS-2.0-AND-EVOLUTION-ARCH` §4 F3 给出了正确骨架（proposal → staging → promotion）。本架构补齐三处它没有的：**ATTRIBUTE 环**（此前是空白，而它是瓶颈）、**SHADOW/CANARY 的量化门**、**MONITOR 的自动回滚**。

### 4.2 每一环的硬约束

| 环 | 输入 | 输出 | 硬约束 | 失败处置 |
|---|---|---|---|---|
| OBSERVE | 全量轨迹 | 失败队列 | 脱敏；subject 不跨 split | 丢弃该条 |
| **ATTRIBUTE** | 失败轨迹 | 8 类标签 + 置信度 | 置信 <0.6 → 人工队列 | **未归因不得进 PROPOSE** |
| PROPOSE | 归因 + 技能池 | 5 类提案 | 每周期 ≤3；每提案 ≤3 轮修订 | 超额拒绝 |
| STAGE | 提案 | 不可变 staging | G0–G2；重算 packageSha | `CANDIDATE_DRIFT` |
| EVAL | staging | evalRun 记录 | ≥20 例、0 回归、≥baseline | `EVAL_BLOCKED` |
| SHADOW | staging | 对比报告 | ≥24h 或 ≥200 session，**≥2 个 harness** | 自动中止 |
| CANARY | staging | 放量数据 | 5% → 25% → 100%，每档 ≥24h | 回退 |
| PROMOTE | 全链证据 | active 切换 | 非自批、`expectedActiveSha` | `*_BLOCKED` |
| MONITOR | 新 active | 新轨迹 | 30 天内回归即回滚 | 自动回滚 |

**ATTRIBUTE 是瓶颈，必须说清**。没有归因的进化 = 拿症状当病因：一个"上下文过载"导致的失败会被误诊成"技能描述不清"，于是技能被改得越来越长，越来越长又加剧上下文过载——**自我强化的退化**。八类归因：

`prompt_ambiguity` / `context_overload` / `model_limit` / `schema_mismatch` / `missing_info` / `upstream_contradiction` / `tool_fault` / `external_change`

这与 `AGENT-PLUGINS-2.0` §5 的失败分类、以及 `IM2A-v2.5.0-EXECUTION-PACK` 的 `terminal.status` / 截断判定是同一套语言，不新造词。

### 4.3 五条进化轴（不同节奏、不同门、不同天花板）

| 轴 | 对象 | 节奏 | 门 | 天花板 | 地板（停摆判定） |
|---|---|---|---|---|---|
| **参数轴** | 阈值、预算、自主度 | 天 | 自动 + 带宽监控 | 单次变动 ≤20% | 30 天无变动 → 查是否冻结 |
| **记忆轴** | facts / patterns / episodes | 实时 | 提案 + 冲突检测 + 衰减 | ≤50 新增/天/agent | 14 天 0 新增 → 观察 |
| **技能轴** | `SKILL.md` 包 | 周 | G0–G5 全 | ≤3 晋升/周期 | 30 天 0 晋升 → **停摆告警** |
| **编队轴** | formation 拓扑 | 月 | 离线回放 + 人工 | 深度 ≤2 / 扇出 ≤5 | — |
| **宪法轴** | SI / 禁令 | 九方 | ADR + 九方门禁 | 每大版本 ≤1 次 | — |

设计原则：**越靠上的轴越快、越自动、越容易回滚；越靠下的轴越慢、越需要人、越不可逆。** 把快轴的自动化能力借给慢轴，是这个系统最可能的崩法。

### 4.4 终止条件与激活条件（写进契约，不是口头约定）

| 条件 | 阈值 | 动作 |
|---|---|---|
| 修订轮次 | 3 | 强制退出，带最优结果升级 |
| 分数平台 | 连续 2 轮无提升 | 退出并升级，不继续烧预算 |
| 提案寿命 | 30 天未晋升 | `EXPIRE` |
| 影子样本 | <200 session 或 <24h | 不得进 CANARY |
| 成本 | 单周期超硬上限 | 中止 + 保留最优 |
| 回归 | eval 或影子任一回归 | 立即 `ABORT`，不"再调调看" |

### 4.5 五种反模式（这是本节最重要的部分）

1. **闸门剧场**：接受率 >60%（什么都批）或 <10%（什么都不批）都是故障。两个指标必须同时可见，单看一个必然退化——`AGENT-PLUGINS-2.0` A17/A18 的配对要求，此处延用并加带宽告警。
2. **自证**：用例由被评者生成、或被评者自己打分。→ 冻结该 eval 集，不计入晋升证据。
3. **退化式进化**：pass 率上升，但正文长度/成本/延迟上升 >20%。→ 视为回退。加了"复杂度税"才能挡住这个。
4. **假稳定**：30 天 0 提案不是"系统稳定"，是**进化停摆**。→ 必须告警，如同高故障率。
5. **单点评估**：只有一个 Evaluator，或只有一种模型评分。→ 需双评或 ≥10% 人工抽查，否则评测盲区会成为系统盲区。

### 4.6 验收标准 AC-E

| ID | 指标 | 阈值 |
|---|---|---|
| AC-E1 | 晋升前具备 ≥20 例 eval + 已录基线 | 100%，0 例外 |
| AC-E2 | 未归因而进入 PROPOSE 的提案 | 0 |
| AC-E3 | 归因分类准确率（≥200 合成失败样本） | ≥80%（v2.6.2）→ ≥90%（N3 后） |
| AC-E4 | 影子样本覆盖 harness 数 | ≥2 |
| AC-E5 | 影子回归自动中止 | 100%，0 次人工发现 |
| AC-E6 | 一键回滚（技能指针） | ≤60s，演练 100% |
| AC-E7 | 晋升精度（滚动 20 次无回归比例） | ≥90%，低于即冻结 |
| AC-E8 | 提案接受率 | 落在 10%–60%，越界告警 |
| AC-E9 | 自批/自评 | 0 |
| AC-E10 | 冻结开关生效时仍发生的晋升 | 0 |

## 5. 50 版分层路线图

### 5.1 版本对象模型

沿用现有双轨制（`IM2A-v2.3.45-SIX-PARTY-DEVELOPMENT-PLAN` §7.2）：平台 tag 与 Go tag **分别记录，不强改同号**。50 个小版本是**平台版本**；Go 网关在自己的 minor 线上走，由 `release-manifest.json` 交叉记录。

### 5.2 节奏规则

`2.5.4 → 3.0.3` 共 50 个 minor。窗口 = **10 版**，每个窗口 = **6 版收尾旧线 + 4 版开新线**，窗口末尾为九方门禁。

| 窗口 | 版本区间 | 主题 | 大版本落点 | 九方 |
|---|---|---|---|---|
| W1 | 2.5.4 – 2.6.3 | 灵魂契约与归因地基 | **2.6.0**（大） | N1 @2.6.3 |
| W2 | 2.6.4 – 2.7.3 | 积累：技能与记忆 | **2.7.0**（大） | N2 @2.7.3 |
| W3 | 2.7.4 – 2.8.3 | 社会：角色/声誉/产权/治理 | **2.8.0**（大） | N3 @2.8.3 |
| W4 | 2.8.4 – 2.9.3 | 自进化闭环 | **2.9.0**（大） | N4 @2.9.3 |
| W5 | 2.9.4 – 3.0.3 | 规模化与灵魂完成 | **3.0.0**（超大） | N5 @3.0.3 |

合计：**1 个超大版本（3.0.0）+ 4 个大版本（2.6/2.7/2.8/2.9.0）**，50 个小版本，5 次九方发布。
校验：6+4 = 10，×5 = 50 ✓。

**为什么大版本落在窗口倒数第 4 版而不是首版**：`.0` 需要 3 个小版本稳定化才敢过九方门；若 `.0` 在窗口首版，门禁时它只有 .0 一个数据点，等于拿未稳定的版本去认证。落在倒数第 4 版，门禁时已有 `.0/.1/.2/.3` 四个数据点。

### 5.3 单版本交付契约（"每次只交付一个小版本"的操作化）

每个小版本必须同时满足：

1. **可独立部署**：不依赖下一版才能运行。
2. **可独立回滚**：有一个明确的回滚点（上一 tag 的资产 + 数据迁移是否可逆必须写明）。
3. **不留半更新状态**：指针/迁移要么完成要么不开始。
4. **对外工具面要么不变，要么显式升版**：13 → 12 这类变更必须写进 release notes，不允许悄悄改。
5. **一条执行验收命令 + 一个负控 + 一条 changelog**。

**禁止**：跨版本的"临时不兼容窗口"；用 feature flag 承载安全边界（安全边界只能靠版本，沿用执行包 §5）。

### 6.4 反仪式化（门禁最容易腐化的地方）

## 7. P0 风险

按"会不会让整件事从根上失效"排序。

### P0-1 提案与暂存同权（已核实）

`server.mjs:363-372` 以同一 `AGENT_NAME` 作 proposer，`:374-384` 以同一 `AGENT_NAME` 作 stagedBy 执行 stage，无角色判定。
**后果**：提案制进化的第一道分权被绕过，v2.6.3 之后的全部"治理完整性"证据都建立在不成立的前提上。
**检出**：以主 Agent 身份调 `curator.stage`。
**处置**：2.5.4 必须修；这是整个 50 版路线的前置条件，不修则 W3/W4 的治理指标全部无效。

### P0-2 灵魂不可观测 = 进化不可归因

无 soulTriad 时，"Agent 变了"无法区分是进化、漂移还是载体回归。
**后果**：所有晋升都不可审计；回滚可能回到一个"当时也没搞清"的状态。
**处置**：W1 全窗口解决（2.5.6–2.5.9），2.6.0 冻结。

### P0-3 声誉可被自证污染

若 eval 用例来自被评者产出、或产出方自评，声誉与晋升同时失效。指标监控（A17/A18）只能事后发现，挡不住结构缺陷。
**处置**：结构隔离（用例生成与评测身份分离 + 盲评）+ 自证用例 100% 拒绝。2.8.4/2.8.5。

### P0-4 主体不可鉴权 → 声誉归属错误

v2.5.3 已知残余：gateway token 无 per-user 身份；session token 是 bearer；`session_token` query 兜底可经 URL/日志泄漏。
**后果**：社会层的所有账本（声誉、产权、制裁）都会记到错误的主体上。**账本记错人比没有账本更危险**，因为它产生虚假的可信度。
**处置**：2.9.4 绑定调用者身份；在此之前，跨租户声誉不合并、不对外声明。

### P0-5 静默降级（跨 harness 时最易发生）

12 适配器仅 1 个 `verified`。一个 harness 静默截断技能正文，行为变化会被误判为"evolution 回退"，进而触发错误的回滚或错误的 patch。
**处置**：SI-4 + `soul-degraded` 事件（2.5.7）；未 `verified` 的 harness 不参与跨端一致性主张。

### P0-6 宪法可被运行时绕过

若 SI 检查器只在 CI 跑，Agent 可通过工具路径绕过。
**处置**：双点（CI + 运行时），且检查器不可配置（2.5.8）。

### P0-7 进化的双向失败

只测精度 → 只晋升必胜的（系统僵化）；只测接受率 → 什么都批（系统腐化）。
**处置**：双带宽 + 停摆告警 + 冻结开关（2.8.8/2.8.9）。

### P0-8 记忆产权泄漏面

`ExportUser/ImportUser` 是整用户级导出。一个 Agent 一旦获得导出权，就获得该主体的全部记忆。
**处置**：2.6.7 收窄到 `scope + 目的 + 审批`；在此之前不开放跨 agent 导出。

### P0-9 成本无上界

自动用例生成 × 自动评测 × 影子流量 = 三重乘数。若无硬预算闸，进化会吃掉全部预算。
**处置**：2.9.6 硬上限 + 中止；每个环单独设预算（§4.4）。

### P0-10 "可回滚"是声明而非事实

v2.4.6 资产校验失败（已核实）。若回滚从未演练，"≤60s"只是文档。
**处置**：2.9.9 四库恢复演练；N4 起门禁要求。

### P0-11 门禁仪式化

45 次检查 + 每期同一脚本 → 评审者停止阅读。
**处置**：每期负控必须红（§6.4）。

### P0-12 拟人化滑移

一旦指标变成"满意度/忠诚度/主动性"，架构就滑向不可验证的叙事，且无法与漂移区分。
**处置**：只用 §3.0 五条判据评估"社会主体"；任何不可检出的属性不作为目标、不作为指标、不写进验收。

| R9 | 永久放逐无人工复核 | 不可修复的惩罚导致行为随机化 | 有期限 + 自动解除 + 申诉 |
| R10 | 用"社会/情感"指标做验收 | 不可检出、不可回滚、不可归因 | 五条判据 + 四条不变量 |
