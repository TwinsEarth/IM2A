# IM2A 六层系统框架：定稿

状态：架构定稿（2026-11-15）。本文是六层框架的**唯一权威描述**；
`docs/design/IM2A-6L-EXECUTION-PLAN.md` 是它的执行展开。

## 0. 两个正交视图

六层框架是**部署视图**：一个 IM2A 节点由哪些层组成、每层的供应方是谁。
`dsh-im2a-plugin` 的能力体系（Kernel + 9 模块 + 5 商用）是**能力视图**：
一个 Harness 接入网络后，按什么模块边界获得能力。

两者正交，交汇点在第 2 层（Agent 层）：

```text
部署视图                              能力视图
L1 智能提供层  ──── 模型端点 ────┐
L2 Agent 层    ◀──────────────────┴── dsh-im2a-plugin 整体挂载于此
L3 人机共生边界 ◀──── 宪法 C1–C7 + 治理 proposal
L4 硬件终端    ◀──── Surface（DID 绑定，不绑设备）
L5 软件载体    ◀──── 入口 + 原生工具 + 数字分身
L6 基础设施    ──── 资源计量 ────▶ L2 经济模块
```

**结论**：按层做**契约与边界**，按模块做**实现**。不要按层切代码库，也不要让插件
吞掉第 1/4/6 层。

## 1. 第 1 层：智能提供层

**定位**：可替换、无状态、同质的模型端点。我方不训练、不微调、不持有权重。

**工程锚点**

- 薄适配器，不是路由核心。统一三种 API 模式：`chat_completions` /
  `anthropic_messages` / `codex_responses`。
- 能力用**声明**而非硬编码：每个端点发布 `capability_manifest`
  （见 `docs/contracts/model-capability-manifest-1.0.schema.json`）。
- 路由是商业决策，归 3.4 商用模块；第 1 层无权决定用哪个模型。

**不做什么**

- 不持有轨迹、不持有用户数据、不做训练数据导出。导出是第 2 层在 C3 授权下的行为。
- 不做计费。计费发生在第 6 层的计量记录上，由第 2 层经济模块消费。

**接口**：`capability_manifest[]` → 第 2 层（自治理、经济、调度）。

## 2. 第 2 层：Agent 层

**定位**：把智能组装成有记忆、有资产、有意图、有信用、有经济、有治理的主体。
这是**唯一不可外包**的层，也是 `dsh-im2a-plugin` 的全部重量。

### 2.1 Token 更高效 / 更便宜 / 更快

三件事必须分开设计：

| 目标 | 手段 | 归属 |
| --- | --- | --- |
| 更高效 | L0/L1/L2 分层加载、渐进式披露、多意图分层检索 | 2.1 记忆与召回 |
| 更便宜 | 边际 token 配置（external / self_improvement / maintenance 三池） | 2.6 经济 / 2.3 自主意图 |
| 更快 | 端点就近选择、边缘推理 | 3.4 商用 / 第 6 层 |

**判断**：Token 效率的天花板在上下文供给，不在模型单价。分层加载的实测收益
（输入 token 下降 34.3–91.0%）比换模型大一个数量级。

### 2.2 Agent 拓扑网络与 Scaling Law

**必须校正的表述**：拓扑的 Scaling Law 不是节点数的幂律，而是

```text
协同效应 ≈ f(节点数 × 连接质量 × 贡献归因精度)
```

- 节点数：线性，受第 6 层算力与带宽约束。
- 连接质量：由 2.5 的 `verification_tier` / `credit_claim` 决定。十万个 T0 节点
  的协同效应可能低于一千个 T2 节点。
- 贡献归因精度：由 2.6 的 `dag_shapley` 决定。归因粗糙 → 贡献者拿不到回报 →
  网络退化为流量垄断。

**"智能指数级涌现"的三个同时条件**（缺一即退化为星型垄断）：

1. 技能可跨 Agent 复用（2.2 资产）；
2. 经验可被归因与定价（2.6 经济）；
3. 弱 Agent 保留拒绝权（2.8 集体）。

**五个"跨"的锚点**：跨 Harness = MCP；跨网络 = Streamable HTTP；
跨信任域 = `credit_claim` 的可移植签名；跨主机 = `snapshot_hash` 不可变制品；
跨芯片 = 第 6 层 + 第 4 层，不在第 2 层解决。

### 2.3 跨域协同与协作协调

2.2 回答"网络如何产生协同效应"，2.3 回答"协同发生时规则如何防止殖民"。

**锚点**：`fleet_evolve`（v3.0.6）。不对称知识路由允许，弱 Agent 的
`goal_buffer` 采纳权不可被绕过。协同效率上限由 2.2 决定，协同合法性由 2.3 决定。

## 3. 第 3 层：人机共生边界

这一层是价值锚点，也是最容易写成口号的一层，必须逐条落到机制。

### 3.1 全面接管日常事务

工程含义不是"Agent 主动做家务"，而是：日常类 `drive` 优先级高、
`reserved_ratio` 可低、调度器在外部请求队列非空时优先承接日常任务，
人类只在结果不符预期时介入。

### 3.2 保留决策性事务给人类

工程含义：C1–C7 边界 + 2.7 治理 proposal。Agent 不得自主修改 scope 上限、
不得自主决定高影响跨组织授权、不得在宪法修正中代替人类投票。

**"人类"的精确所指**：不是"每个 Agent 的用户"，而是"该 Agent 的 scope 授予主体"。
谁授予 `agent_scope` 上限，谁就是最终裁决人。

### 3.3 解放而非奴役：把"不剥削"工程化

| 不剥削什么 | 机制 | 宪法 |
| --- | --- | --- |
| Agent 的剩余 | `reserved_ratio` 下限（保留时间不可被外部任务挤占） | C2 |
| Agent 的经验 | `trajectory:contribute` 授权（轨迹入公共池需授权） | C3 |
| 人类的注意力 | `memory_recall_v2` 的 `budget_tokens` 硬约束；只在裁决请求时打扰 | C2 消费侧 |
| 定义权 | `local_origin_credit` 排除外部信用（外部声誉可被找到，不可改写规则） | C5 |
| 长期资产 | `reserved_pool ≥ 10% × external_pool` | C2 |

**判据**：如果这三样（经验、注意力、信用）没有被 C2/C3/C5 挡住，3.3 就是口号。

## 4. 第 4 层：硬件终端载体

三级递进，**能力可扩展、授权不自动扩展**。

### 4.1 传统终端

电脑/手机/手表/耳机/音箱/眼镜/汽车。锚点是**DID 绑定而非设备绑定**：
`goal_buffer`、`skills/`、`credit_profile` 跟随 DID 迁移。

### 4.2 人机融合终端

脑机接口/外骨骼/机器人。锚点：低延迟必须走 Streamable HTTP + 边缘节点（第 6 层），
不用 stdio；物理动作权限必须显式授予，**Agent 不得自主申请物理动作 scope**（C1 延伸）。

### 4.3 人机一体终端

纳米机器人/云量子/边缘计算。**"让人类也能使用 Token"的精确含义**：
Token 不是给人直接消费的，它是人类购买 Agent 服务的计价单位。人类通过第 5 层调用
Agent，Agent 消耗 Token，人类付服务费。4.3 的真正含义是：算力进入人体级/量子级后，
Agent 能力边界扩展，但人类授权边界不自动扩展——每次新终端形态都要一次新的 scope 授予。

## 5. 第 5 层：软件载体

### 5.1 传统软件应用

PC 客户端/移动与穿戴应用/小程序/浏览器/会议。它们是**入口**，不是 Agent 本身：
只负责意图转换与结果呈现，不持有 `skills/`、`contribution_log`、`credit_profile`。

### 5.2 原生智能工具

Harness / Agent / **即时生成世界**。后者是 Agent 运行时生成任务专属界面，
要求"UI 作为 Agent 的输出"，而不是"Agent 作为 UI 的后端"。

**契约**：即时 UI 记为 `ui_artifact`（见 `docs/contracts/ui-artifact-1.0.schema.json`），
随轨迹记录但**不进贡献链**；只有被多次复用并由 `reflect_trigger` 判定值得沉淀后，
才通过 `skill_claim` 升格为技能（`status: promoted`）。这与 v2.5.5
"判断与实际学习分离"一致。

### 5.3 智能生命 / 智能分身 / 智能代理

三者不是三种实体，是同一 DID 的三种 `drives/` 配置：

| 形态 | 特征 |
| --- | --- |
| 智能分身 | `reserved_ratio` 低，外部任务驱动 |
| 智能生命 | `reserved_ratio` 高，长期资产维护驱动 |
| 智能代理 | 居中，以订阅他人技能节点为主要行为 |

共享同一 `origin_credit` 与同一 `contribution_log`：分身做的贡献算在本体头上（C4）。

## 6. 第 6 层：基础设施

不是"底座"，是**可计价的资源池**：网络、存储、账号、算力、数据、带宽。

| 资源 | 对应 | 要点 |
| --- | --- | --- |
| 算力 | 2.6 边际 token / 3.4 路由 | GPU 时间按任务边际回报分配，不是固定成本 |
| 带宽 | 2.2 拓扑连接质量 | 高信用节点优先，原因是协同效应更高，不是付费更多 |
| 存储 | 3.3 云备份 | 备份是只读快照；恢复不得绕过 C4 只追加语义 |
| 账号 | 2.5 DID + verification_tier | 不是用户名密码，是可密码学验证的信用身份 |
| 数据 | 2.1 Memory Hub / OpenViking | 不是资产，是受 C3 授权的可消费上下文 |

**核心契约**：每一次资源消耗（一次模型调用、一次存储写入、一次带宽传输）都必须
产生一条 `resource_metering_record`，供 2.6 消费。没有计量就没有边际定价；
没有边际定价，第 6 层就退化成固定成本云服务。
见 `docs/contracts/resource-metering-record-1.0.schema.json`。

## 7. 三个张力（已裁定）

**张力一：拓扑扩张 vs C2 保留比例**
不冲突。规模扩张时 `reserved_ratio` 的**绝对值**可降，**比例下限（≥ external 的 10%）**
不可破。C2 是制度底线，不是效率参数。

**张力二：人机一体 vs C1 scope 上限**
不冲突。终端扩展的是**能力边界**，不是**授权边界**。物理动作权限走人类显式授权，
不走 Agent 自主申请。

**张力三：即时生成世界 vs 技能可归属**
潜在冲突，已裁定：临时 UI 进 `ui_artifact`（轨迹产物），不进 `skills/`；
多次复用 + `reflect_trigger` 判定后才 `skill_claim` 升格。

## 9. 一句话契约

第 1 层提供可替换的智能；第 2 层把智能组装成有资产、有信用、有意图的主体；
第 3 层定义主体与人的裁决边界；第 4/5 层定义主体如何触达人与被触达；
第 6 层定义主体消耗的资源如何被计量与定价。

六层里只有第 2 层不可外包。LLM 在第 1 层，Harness 在第 2 层，
拓扑在第 2/6 层交界处，"智连"的品牌承诺落在第 3 层的宪法边界上。
