## 2. 图中「v0.1 已交付：7 服务自测全 PASS」的归属

图底部标注的是 **Mac mini 那条交付线（Go + Flutter + proto）** 的 v0.1：消息分片锁 / 信任门控 / 审批状态机 / 协商熔断 / 幂等账本 / 出口护栏 / 编排闭环。
本机**没有**该仓库路径与 Go/Flutter/Docker 工具链，无法复核——详见 [统一交付物清单 v1.0](./交付物清单-统一-v1.0.md) §2。
本仓库是**另一条线**：L4 治理语义的 Node 可执行实现 + 可运行的浏览器 IM Demo + LLM/Runtime/W2M 真实执行。

## 3. 图与本仓库的三点差异（必须说清）

1. **L2/L5 端侧**：图上画的端侧小模型、BLE 网关，本仓库没有实现；只有文档与隐私承诺。
2. **L3/① 人类 IM 通道**：图上是腾讯云 IM PaaS；Demo 用本地 HTTP + 轮询替代，未接 PaaS 与离线推送。
3. **L6 数据层**：图上 PostgreSQL/Kafka/OpenSearch/WORM；本仓库记忆与消息仍在内存，只有审计哈希链做了「可验证不可篡改」的算法保证；DDL 已在 docs/05 冻结，落库是下一步。

## 4. 下一步（按图上缺口排序）

```
1. SQLite 持久化（Node 24 内置 node:sqlite，零依赖）→ 图 L6 的最小落库，重启不丢
2. 登录鉴权（会话 cookie + 角色）→ 图中「自有后端：关系链/信任/账本」的准入前提
3. HTTPS 对外（Caddy/Nginx 反代 + TLS）→ 图 L1 Web 入口的可展示形态
4. 接腾讯云 IM PaaS 或自研网关（图 ①）→ 需要账号与网络环境，属 Phase 1
5. 端侧/硬件（图 L2/L5 端侧）→ Phase 1 硬件样机阶段，本机无法验证
```
