# 08 · 运营、客服、运维与合规

> 文档定位：产品能上线，不只是代码能跑。本文回答四件事——
> **资质怎么排期、内容怎么审、Agent 怎么被审计、出事了谁来兜**。
> 上游契约：`contracts/INTERFACES.md` v1.0（`TICKET_STATE`、`MSG_STATE`、`TASK_STATE`、`VERDICT`、
> `DECISION`、`GATE_CODE`、`ENTRY_TYPE` 等枚举逐字引用）。
> 标记：**⚠ 需复核** = 需法务/资质代办/财务/供应商确认，不得作为对外承诺；
> **⚠ 待定** = 需产品与运营在开工前拍板的初始值。

## 2. 内容审核闭环

### 2.1 链路与 SLA

| 环节 | 对象 | 手段 | 时效 SLA | 失败兜底 |
|---|---|---|---|---|
| 机审-语音 | 耳机上行语音（ASR 文本 + 声学特征） | 实时敏感词/风险模型；只审**命中的语音片段** | 流式 ≤200ms/片段 | 超时 → 走文本机审 |
| 机审-文本 | Agent 外发内容、协商摘要、付费消息来意 | `EgressGuard.inspect()` 规则（身份证/银行卡/转账话术/辱骂/外链/超长）+ 语义模型 | 同步 ≤120ms（阻塞外发） | `VERDICT.REVIEW` 转人工；`BLOCK` 直接拦 |
| 机审-图片/文件 | 头像、名片、附件 | 哈希黑名单 + OCR + 图像模型 | ≤800ms | 失败 → 仅文本可见 |
| 人审-初审 | `VERDICT.REVIEW` 队列 | 人工复核 | **≤30 分钟**（工作时段）/ ≤2 小时（夜间） | 超时自动 BLOCK（宁严勿松） |
| 人审-复审 | 用户申诉 | 双人复核 | ≤24 小时首响，≤72 小时结论 | 超时按「用户胜诉」处理并记录 |
| 处罚 | 确认违规 | 分级处置（见 2.4） | 结论后 ≤1 小时执行 | 处罚可申诉一次 |

### 2.2 三道机审的差异化标准

| 通道 | 从严理由 | 判定阈值（初始 ⚠ 待定） |
|---|---|---|
| Agent 外发内容（含协商内容） | Agent 代表用户说话，错了是平台责任 | 命中任一 BLOCK 规则即拦；语义风险 ≥0.85 → REVIEW |
| 协商摘要（陌生人） | 诈骗高发区（冒充熟人/投资/贷款） | 转账/汇款话术一律 BLOCK，并通知接收方 Agent |
| 付费消息来意 | 付费是诈骗的天然话术钩子 | 预审规则 + 机审双过；任何「承诺收益」类关键词直接 REFUSED |

### 2.3 误杀与漏放目标

| 指标 | 目标 | 采集方式 | 责任 |
|---|---|---|---|
| 机审误杀率（正常内容被 BLOCK） | **≤0.5%** | 每周抽样 500 条人工复核 | 内容安全 |
| 人审误判率 | ≤2% | 申诉推翻率 | 内容安全 |
| 漏放率（违规内容未拦） | ≤0.1%（重大违规 0） | 举报复核 + 外部抽检 | 内容安全 |
| 审核超时率 | ≤1% | 工单系统 | 客服主管 |
| 申诉处理时长达标率 | ≥95% | 工单系统 | 客服主管 |

### 2.4 处罚分级

| 级别 | 触发 | 处置 | 申诉 |
|---|---|---|---|
| L1 提醒 | 首次轻微（外链、擦边话术） | 站内提示 + 内容不下发 | 可申诉 |
| L2 限权 | 重复 L1 或付费消息恶意营销 | 7 天内禁止发起陌生人付费消息、Agent 外发降级为需审批 | 可申诉 |
| L3 封禁 | 诈骗、色情、威胁、冒充 | 封号 + 账本冻结（`ENTRY_TYPE.REFUND` 单独处理） | 一次申诉，双人复核 |
| L4 移交 | 涉嫌违法 | 固证 + 移交执法（见 §3.4） | — |

### 2.5 出口护栏与内容审核的关系（常被混淆）

| 维度 | 出口护栏 `EgressGuard` | 内容审核 |
|---|---|---|
| 时机 | **同步、前置、阻塞**外发 | 异步 + 抽检 + 申诉 |
| 目的 | 不让平台成为违规内容的传输通道 | 兜底、追责、改进模型 |
| 结论 | `PASS` / `REVIEW` / `BLOCK`（契约枚举） | 工单结论（通过/违规/处罚） |
| 关系 | 护栏是第一道闸，审核是闸后的水位监控；**护栏 BLOCK 的内容永远不会进入审核队列**（只进审计与举报） | |

## 3. Agent 行为审计与可解释性运营

### 3.1 审计事件模型（与契约 §0 对齐）

统一事件：`{ at, actor, action, target, decision, detail }`，另加 `traceId` 串联一次任务全链路。
所有治理动作（审批、门控、协商、扣费、权限变更、客服处置）必须落审计；审计表只追加，保留 ≥6 个月（⚠ 依等保与行业要求可延至 12 个月）。

### 3.2 决策轨迹回放（运营工具）

| 能力 | 说明 | 使用者 |
|---|---|---|
| 单链回放 | 输入 `traceId` → 时间轴还原 Skill 调用/门控判定/协商轮次/审批动作 | L3 安全合规、算法 |
| 差异对比 | 同 `topic` 两次协商的轮次、token、结论差异 | 算法 |
| 证据包导出 | 一次争议的全链路导出（脱敏） | 法务 |
| 用户侧可解释 | 用户可在巡视态看到「为什么这么建议」（3 层钻取，见 07 §2.2） | 用户 |

### 3.3 异常行为告警与自动降级

| 编号 | 异常 | 阈值（初始 ⚠ 待定） | 自动动作 | 通知 |
|---|---|---|---|---|
| A-01 | 子 Agent 频繁调用某 Skill | 单 Agent 单 Skill >20 次/分钟 或 >200 次/天 | 该 Agent 降级为「只读 + 需审批」 | 用户 + 值班 |
| A-02 | 超预算 | 当日花费 >80% `budgetCentsPerDay` | 冻结该 Agent 支付能力，剩余预算耗尽前人工确认 | 用户 + 财务 |
| A-03 | 触碰信任边界 | 单日 `TRUST_TOO_LOW`（DENY）≥3 次 | 暂停该 Agent 对外动作 1 小时 | 用户 + 安全 |
| A-04 | 协商失控 | 同一 `topic` 当日 `INPUT_REQUIRED`/`AUTH_REQUIRED` >3 次，或持续 `WORKING` >10 分钟 | 强制 `CANCELED` 并上抛摘要 | 用户 |
| A-05 | 出口拦截异常 | 单 Agent 每小时 `VERDICT.BLOCK` >5 次 | 该 Agent 外发全部转人工审批 | 安全 |
| A-06 | 付费消息异常 | 单账号单日 `DAILY_CAP_EXCEEDED` 触发 ≥3 次，或退款率 >20% | 限制发起 + 人工核查 | 风控 |
| A-07 | 账本不平 | 日切差异 ≠ 0 | 停止自动结算，转人工 | 财务 + SRE |

**自动降级的铁律**：降级只允许「收紧」，不允许「放开」；恢复必须人工。每次降级写审计并推送给用户（不可静默——静默降级会毁掉信任）。

### 3.4 数据调取与执法配合

| 场景 | 流程 | 时限 |
|---|---|---|
| 用户本人导出 | App 内自助导出（审批记录/审计/传输事件） | ≤7 天 |
| 律师函/司法调取 | 法务核验文书 → 安全合规导出 → 双人签字 | ≤3 工作日（法定除外） |
| 公安调取 | 核验警官证与调取函 → 分级审批 | 紧急 ≤2 小时，常规 ≤24 小时 |
| 未成年人保护 | 涉嫌侵害 → 立即固证 + 上报 | ≤1 小时 |

## 4. 「蒸馏健康度」：让 Agent 越用越懂你，而不是越用越跑偏

### 4.1 反馈信号来源（不是改模型权重）

| 信号 | 契约落点 | 对阈值的作用 |
|---|---|---|
| 一键通过 `APPROVE` | `decide({action:'APPROVE'})` | 该域该额度档**放宽**（自主阈值上调一档，需连续 N 次） |
| 修改 `MODIFY` | `decide({action:'MODIFY', patch})` | 该域**不动**，记录 `patch` 差异用于规则校准 |
| 驳回 `REJECT` | `decide({action:'REJECT'})` | 该域**收紧**（阈值下调，或强制需审批） |
| 超时未处理 `EXPIRED` | `escalateOverdue()` 后仍无动作 | 降低该域推送优先级（避免骚扰） |

### 4.2 指标与告警

| 指标 | 定义 | 健康区间（⚠ 待定） | 漂移告警 |
|---|---|---|---|
| 自主完成率 | Agent 无需审批完成数 / 总任务数 | 稳态 55%–75% | 周环比 −5pp |
| 审批通过率 | `APPROVED` / (`APPROVED`+`REJECTED`) | 70%–90% | <60% 或 >95% |
| 驳回率 | `REJECTED` / 已决总数 | 5%–20% | >25% |
| 修改率 | `MODIFIED` / 已决总数 | 5%–15% | 周环比 +10pp |
| 决策中位时间 | 卡片展示→动作 | ≤30s | >45s |
| 每域样本量 | 该域周已决数 | ≥50 | <30 时不做阈值调整 |

**校准规则**：只有样本量达标且连续 2 周同向，才允许调整一次阈值（步长 1 档，单周最多 1 次）；
调整必须写审计并在「管家学习记录」中展示给用户（可撤销）。

## 5. 分层客服

| 层 | 覆盖问题 | 人员 | 首响 SLA | 解决 SLA | 权限 |
|---|---|---|---|---|---|
| **L1 机器人** | 硬件连接/配对/充电、计费规则解释、权限设置指引、订单物流查询 | 自动（知识库 + 意图识别） | 即时 | ≤2 分钟 | 只读 + 自助操作引导 |
| **L2 人工** | 退款争议、隐私投诉、封号申诉、账单异常、硬件换修 | 自有客服 | **≤24 小时**（工作时间 ≤2 小时） | ≤48 小时 | 退款 ≤¥200、换修、解封初审 |
| **L3 安全合规** | 审核申诉、执法调取、未成年人保护、重大舆情/隐私事件 | 安全合规值班 | **7×24 值班，≤1 小时** | 按事件分级 | 封号、数据调取、对外口径 |

### 5.1 升级与转派规则

| 触发 | 动作 |
|---|---|
| L1 连续 2 轮未解决 | 转 L2，附会话摘要 |
| L2 涉及退款 >¥200 / 隐私 / 人身安全 | 立即转 L3，同时拉群 |
| 同一问题 24h 内 ≥3 位用户反馈 | 自动升级为「疑似故障」，通知 SRE |
| 任何用户提出「数据删除」 | 转 L3，按 `MemoryStore.purge()` + 存储级联 24h 内完成 |
| L3 判定为 P0 事件 | 启动 08 §6 故障分级流程 |

### 5.2 工单标签（最小集）

`硬件-连接` / `硬件-续航` / `硬件-售后` / `计费-扣费争议` / `计费-退款` / `权限-信任档位` /
`内容-审核申诉` / `内容-封号` / `隐私-数据删除` / `隐私-麦克风` / `Agent-行为异常` / `其他`。

## 6. 运维（SLO / 告警 / On-call / 灰度 / 对账）

### 6.1 SLO 与告警阈值

| 编号 | 指标 | SLO | 告警阈值 | 级别 |
|---|---|---|---|---|
| S-01 | 审批 API 可用性 | 99.9%/月 | 5xx >0.5% 持续 5min | P1 |
| S-02 | `decide` 时延 | p95 ≤300ms | p95 >800ms 持续 10min | P2 |
| S-03 | `GET /api/state` 时延 | p95 ≤200ms | p95 >500ms 持续 10min | P3 |
| S-04 | 审批卡片端到端可见时延 | p95 ≤2s | p95 >5s 持续 10min | P2 |
| S-05 | 账本日切差异 | = 0 笔 | 差异 ≥1 笔 | P0 |
| S-06 | 协商任务成功率 | ≥99%（非用户取消） | <97% 持续 30min | P2 |
| S-07 | 出口护栏调用成功率 | ≥99.95% | 任何 5xx | P1 |
| S-08 | 消息投递延迟（IM 通道） | p99 ≤1s | p99 >3s 持续 5min | P2 |
| S-09 | 崩溃率（客户端） | <0.1% | >0.1% 触发灰度暂停 | P1 |
| S-10 | 审核队列积压 | <500 条 | >1000 条或最老 >2h | P2 |

### 6.2 故障分级与响应

| 级别 | 定义 | 响应 | 恢复目标 | 通报 |
|---|---|---|---|---|
| P0 | 资金错误、数据泄露、全站不可用、账本不平 | 5 分钟 | ≤30 分钟止损 | 全员 + 法务 + 公关 |
| P1 | 审批主链不可用、护栏失效、大面积崩溃 | 15 分钟 | ≤1 小时 | 值班 + 产品 |
| P2 | 局部功能降级（协商/巡视/推送） | 30 分钟 | ≤4 小时 | 值班 |
| P3 | 单点体验问题 | 4 小时 | ≤3 工作日 | 工单 |

On-call：SRE 1 主 1 备（周轮值），安全合规 1 人（7×24），产品经理 1 人（工作时段）；
升级路径：值班 → TL（15 分钟无响应）→ 技术负责人 → CTO。

### 6.3 灰度与回滚

| 阶段 | 流量 | 时长 | 门禁 |
|---|---|---|---|
| G0 内部 | 员工 + 种子用户 200 人 | 2 周 | 崩溃率 <0.1%，无 P0 |
| G1 | 1% | 24–48h | 崩溃率 <0.1%，SLO 达标，无资金错误 |
| G2 | 5% | 24–48h | 同上 + 客诉率 <0.5% |
| G3 | 10% | 24–48h | 同上 + 审核误杀率达标 |
| G4 | 30% | 24–48h | 同上 + 留存不劣化 |
| 全量 | 100% | — | 连续 3 天指标稳定 |

回滚触发（任一即回）：崩溃率 >0.1%、`decide` 失败率 >0.5%、账本差异 ≥1 笔、隐私相关客诉 ≥2 条/小时。
回滚 SLA：服务端 ≤10 分钟（保留 N-1 镜像），客户端 ≤2 小时（配置开关）/ ≤24 小时（发版）。

### 6.4 账本对账与日切（`ENTRY_TYPE` = CHARGE / REFUND / SETTLE）

| 步骤 | 时间 | 内容 | 责任 |
|---|---|---|---|
| 1 日切 | T+1 00:30 | 冻结 T 日账本快照，禁止补写 | 财务系统 |
| 2 内部对账 | T+1 01:00 | 账本 ↔ 订单 ↔ 审批单三方勾对 | 财务 + 后端 |
| 3 通道对账 | T+1 09:00 | 账本 ↔ 支付通道流水（金额/笔数/手续费） | 财务 |
| 4 差异挂账 | 发现即挂 | 差异进「待查池」，**不允许直接改账**（只追加冲正 `REFUND`/`SETTLE`） | 财务 |
| 5 闭环 | ≤3 工作日 | 差异归因 + 补记 + 报告 | 财务 + SRE |
| 6 月度结算 | 每月 5 日 | `SETTLE` 生成，平台抽成与创作者/服务方分账 | 财务 |

**硬约束**：账本只追加；重复投递以 `idempotencyKey` 去重（分布式部署时该键为 DB 唯一索引）；
`pay:<messageId>` 是付费消息的唯一扣费键，对账时按此键核对。
