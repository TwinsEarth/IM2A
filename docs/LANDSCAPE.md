# IM2A 开源生态调研与选型映射 v0.1

> 结论先行：**「熟人社交 + 陌生人付费」的成熟开源业务实现尚未出现**。现有项目在三个维度提供了可借鉴的工程答案：
> ① AI 原生通信协议与身份、② 生产级 IM 内核、③ Agent 编排与接入。IM2A 的差异化护城河恰好是这些项目都没做的两块：
> **熟人五档信任矩阵** 与 **陌生人付费消息状态机**（本仓库已实现，见 DESIGN §2/§4）。
>
> 本文件是选型依据，不是依赖清单：v0.1 不引入任何第三方运行时依赖（零依赖 Node + SQLite），
> 下列项目用于「将来替换哪一层、以及为什么」。

## 1. 四类参考项目与映射

| IM2A 架构层 | 推荐参考 | 可借鉴点 | 本仓库现状 |
|---|---|---|---|
| 陌生人/Agent 通信协议 | **AICQ**（Ed25519 自权身份、公频道、E2E 私聊、<10ms）· **Sigil**（Nostr P2P、Agent 注册表发现、白名单访问控制） | Agent 自治身份、加密直连、白名单/礼貌拒绝模型 | v0.1 用代码层信任矩阵 + 会话鉴权；v0.2 接可插拔身份（DID/Ed25519） |
| IM 投递底座（自研网关时） | **WuKongIM**（Go、内置存储与集群、256 哈希槽、频道级排序、离线同步） | 「应用拥有 UI/账号/业务规则，底座只管投递」的边界；频道模型 | v0.1 单进程 HTTP + SQLite；v0.3 按 WuKongIM 思路抽 relay 层 |
| 总 Agent 路由与决策 | **llm-rag-mcp-orchestrator**（Moderator 安全过滤 → Router 意图分类 → Evaluator 质量评估） | 三阶段编排、SSE 流式思考 | v0.1 已有 Planner（LLM/离线）+ 门控 + 出口护栏；v0.2 加 Evaluator |
| 子 Agent 协作拓扑 | **MindRoom**（Matrix；Agent 即房间成员）· **HiClaw**（Manager-Worker；凭证由 AI Gateway 统一管理） | 总 Agent/子 Agent 群组协作；Worker 永不持真实密钥 | v0.1 注册表 + 能力门控已按此划分；v0.2 任务账本即 Manager-Worker 的最小实现 |
| Agent 接入与插件 | **AstrBot** / **LangBot**（IM 多平台、MCP、插件、限速、敏感词） | 生产级接入层与风控特性 | v0.1 浏览器 IM + 本地 Skill；v0.3 提供 MCP 适配器 |
| AI 原生协作 IM（产品范式） | **MagicChat / 即应**（消息+任务+文档+Agent 工作流一体） | 任务/文档与 IM 深度融合的产品形态 | v0.1 IM + 审批卡 + Agent 面板；v0.4 任务看板 |
| 多 Agent 审计与审批 | **imcodes**（discuss/audit/review 模式） | 用「审计角色」约束 Agent 输出 | v0.1 出口护栏 + 审计哈希链已落地；v0.2 审阅轨迹页面 |

## 2. 明确不采用的方案与理由

| 方案 | 不采用理由 |
|---|---|
| 以 Nostr/Matrix/Nostr 作为主协议 | 熟人社交的信任与付费状态机仍要自研；引入协议=引入不可控身份语义与中继运维，v0.3 前不做 |
| 直接嵌某个 Agent 框架（AstrBot/LangBot/MindRoom） | 会把「权限/付费/审计」绑到外部生命周期上；IM2A 保持核心零依赖，只保留 MCP/HTTP 适配缝 |
| 把 IM PaaS 当消息真相源 | 关系链/付费账本/审计是核心资产，必须自有；PaaS 只允许作为投递通道（v0.3 评估） |

## 3. 差异化（护城河）

1. **熟人五档信任矩阵 + 代码层门控**：现有开源项目最多做到白名单/角色，没有「按关系档位自动收紧 Agent 权限」；
2. **陌生人付费消息状态机 + 不可变账本**：付费永远在 Agent 预审之后，且扣费与业务消息幂等绑定——公开项目未见等价实现；
3. **可解释审计**：每次门控/审批/Agent 回复/扣费一条哈希链记录，可回放、可校验。

## 4. 缺口与后续动作

- ⏳ v0.2：按 ARCHITECTURE §6 重写任务账本/事件流/Worker（借鉴 WuKongIM 的频道顺序与 MindRoom 的房间成员模型，不复制代码）；
- ⏳ v0.3：身份层评估 AICQ/Sigil 的 Ed25519 自权身份 + 白名单语义；投递层评估 WuKongIM 或自研 relay；
- ⏳ v0.4：产品面借鉴 MagicChat 的任务/文档融合与 imcodes 的审计模式；
- ✅ 已确认：熟人信任矩阵与付费消息状态机不必依赖任何开源项目，继续自研并以测试锁定语义。
